# 기준금리 변경일과 원문 값 찾기

한국은행 기준금리 추이에서 2020년 5월 28일~2023년 1월 13일의 연속 11개 행을 사용했다. 검색 구현과 후보를 보지 않은 담당자가 질문과 정답 행을 정했고, 첫 검색 전에 `0274ed5`에 저장했다. 네 문항은 표 안에 답이 있다. 이 중 하나는 이웃 행에서 가져온 잘못된 금리를 기사에 적어도 해당 날짜의 원문을 찾는지 묻는다. 다섯 번째 문항의 날짜는 발췌 범위 밖이다. [한국은행 원표](https://www.bok.or.kr/portal/singl/baseRate/list.do?dataSecd=00001&menuNo=200643) · [질문과 정답](holdout.json) · [전사 기록](source-note.md)

| 실행 | 첫 후보가 정답 | 상위 세 후보에 정답 | 발췌 범위 밖 날짜의 후보 수 |
|---|---:|---:|---:|
| 첫 검색 | 2/4 | 3/4 | 2 |
| 같은 질문으로 수정 후 재시험 | 4/4 | 4/4 | 0 |

첫 검색에서 2.25%의 변경일을 물으면 머리글만 나왔다. 재시험에서는 2022년 7월 13일 행이 첫 후보였다. 2022년 4월 14일을 1.25%로 잘못 쓴 문항은 두 판본 모두 당일의 1.50% 행을 먼저 보여 줬다. 원표에는 있으나 발췌에 없는 2020년 3월 17일 변경을 물으면 수정판은 해당 날짜 행이 빠졌다고 표시한다. [첫 결과](first.json) · [재시험 결과](retest.json)

두 입력 형식을 대조했다. 동결한 문항의 표에는 날짜가 한 칸이고 머리글에 %가 있다. 실제 웹 표는 연도와 월·일이 별도 칸이고 단위는 표 밖에 있다. 한국은행 HTML 표의 머리글과 11개 행을 탭으로 옮겨 같은 질문을 다시 실행했다. 두 형식에서 후보 순위는 같았다. 실제 셀 형식으로 단위를 확인해야 하는 세 질문에는 원표의 단위를 대조하라는 안내가 붙었다. 같은 11개 관측값을 사용했으므로 두 번의 독립 실험으로 합산하지 않는다. [원표 셀 텍스트](source-table.tsv) · [원표 셀 재시험](source-retest.json)

지표는 정답 행이 검색 후보에 들어왔는지를 센다. 이 문항은 수정 과정에서 다시 사용했다. 새 기관이나 낯선 표에서의 검색 성능, 실제 편집자의 시간 절감률, 최종 기사 정확도는 별도로 측정해야 한다.

저장소 루트에서 현재 판본을 재시험하려면 아래 명령을 실행한다. 첫 판본을 재현할 때는 `git archive 0274ed5 docs/reader`로 꺼낸 판본의 `docs/reader`를 첫 번째 인수로 사용한다.

```sh
trial=experiments/evidence-retrieval-transfer/base-rate-dates
score=experiments/evidence-retrieval-transfer/nov25/score.cjs
node "$score" docs/reader "$trial/holdout.json"
node "$score" docs/reader "$trial/holdout.json" "$trial/source-table.tsv"
```
