# 원문 전체를 보존하는 최소 수정 절차

이 절차는 [동결 작성 지시](protocol/writer-v2.md), [독립 감사 지시](protocol/audit.md), [사전등록](PREREGISTRATION.md)을 실무 순서로 풀어 쓴 것이다. 아래는 실행 규칙이며 이번 기사들의 성공·완료 판정이 아니다. 원문 O와 검사 입력 C는 동일하고, 근거 S는 확보 범위·버전·시점이 명시된 자료 묶음이다. 원문과 근거 어느 쪽도 자동으로 정답이 되지 않는다.

1. **정확한 원문 구간으로 보존할 관계를 기록한다.** 제목·부제·사진 설명·본문과 확보된 근거 전체를 처음부터 끝까지 읽는다. 주장과 발언자, 비판과 대상, 조건과 결론, 수치와 분모, 사건 시점과 후속 정보를 연결하는 짧고 정확한 원문 인용을 남긴다. 의미가 문장 사이에 걸쳐 있으면 떨어진 구간을 함께 연결한다. 다른 문장에 이미 제한 조건이 있는지 확인한다. 이 기록은 다시 읽을 때의 단서이며 완전한 보호 목록이나 정답표가 아니다.

2. **필요성이 입증된 국소 패치만 만든다.** 같은 대상·행위자·시점·단위·범위·귀속에서 근거와 모순하는 중요한 명제, 또는 빠지면 결론이 달라지는 조건을 특정한다. 선택적 설명·문체 선호·가치판단 차이는 필수 수정으로 만들지 않는다. 필요성, 근거 지지, 나머지 의미 보존, 문맥 안전성이 모두 확인될 때만 수정한다. `before`는 입력에서 정확히 한 번 나타나는 비어 있지 않은 원문이고 `after`는 충분한 최소 대체문이다. 패치는 겹치지 않아야 하며 함께 바뀌어야 의미가 유지되는 상대 패치를 `depends_on`으로 연결한다. 근거 부족을 곧 거짓으로 바꾸거나, 보도된 발언의 강도를 편집자 판단으로 낮추지 않는다.

3. **같은 입력과 근거로 인용·동시 적용·전달을 검사한다.** `original_quote`와 `candidate_quote`는 모두 수정 전 입력 O=C의 정확한 구간이어야 한다. 새 문구는 `after`와 `full_edited_article`에만 넣는다. 출처 ID는 실제 입력 ID와 일치시키고 위치와 짧은 정확한 근거 인용을 따로 남긴다. 모든 패치를 원래 위치에 동시에 적용한 결과와 실제 제출한 전체 수정문이 글자 단위로 같아야 한다. 패치 밖 공백도 임의로 바꾸지 않는다. 필수 상대 패치 누락·원문에 없는 앵커·부분 출력·다른 입력의 ID·매핑 또는 해시 불일치가 있으면 전달을 중단한다. 상호 의존 패치는 원자적 묶음으로 검사하며 안전성을 확인하지 않은 일부만 전달하지 않는다. 새 엄격 검사 어댑터와 원자적 적용기의 호출 범위는 [코드 감사](code-audit/README.md)에 명시되어 있다. 기계 통과만으로 의미나 근거가 입증되지는 않는다.

4. **완성문 전체를 별도 문맥에서 독립 감사한다.** 감사자는 먼저 같은 원문·근거·메타데이터만으로 필요한 수정과 중요한 관계를 읽고 PRE를 저장한다. 그다음 익명화된 작성물, 기계 적용문, 실제 전체 수정문을 읽어 JUDGMENT를 별도 저장한다. 원문→완성문의 새 손실과 근거→완성문의 지지 여부를 비교하고 작성자가 기록하지 않은 부분도 확인한다. 이후에만 출력 전에 동결된 독립 기준을 열어 FINAL의 별도 비교로 기록한다. 이전 판단과 기준 분모를 소급해서 덮어쓰지 않는다. 검출, 안전하게 전달된 수정, 불필요 수정, 새 손실, 정당한 보류를 분리한다. AI 감사의 다수결·확신도를 진실 기준이나 인간 검증으로 보고하지 않는다.

5. **불확실한 부분만 보류하고 위험한 변경은 되돌린다.** 수정 필요성이나 근거가 미해결인 명제, 함께 적용해야 할 패치가 빠진 묶음, 다른 의미의 손실이 남은 변경은 해당 범위에서 멈춘다. 이미 오류로 확인한 원문을 단순 복원해야 한다는 뜻은 아니다. 근거가 있는 안전한 대체 수정이 있으면 다시 검사하고, 없으면 미해결 상태를 표시해 전달하지 않는다. 무관한 자료 공백 때문에 안전한 별도 수정을 전부 보류하지 않는다. 필요한 수정이 확립되지 않은 `no_change`와 식별된 문제가 미해결인 `hold`를 구분하며, 둘 다 기사 전체의 진실 인증이 아니다. 재개할 정확한 근거·판단·전달 조건을 기록한다.

운영 중단 조건은 다음처럼 확인 가능한 사건으로 기록한다.

| 중단 사유 | 멈출 범위와 재개 조건 |
| --- | --- |
| 근거 부족 | 주장에 적용되는 원문 구간·자료 버전·대상/시점이 없거나 상충하면 해당 수정을 보류한다. 필요한 논문 구간·공식 기록을 지정하고 실제 확보 후 다시 대조한다. 초록만으로 특정 실험 결과를 만들어내지 않는다. |
| 필요성 미확정 | 누락이 결론을 바꾸는지, 이미 다른 문장이 조건을 제공하는지 확인되지 않으면 추가하지 않는다. 사실·해석·가치 이견을 구분해 문장과 이유를 남긴다. 반복 AI 합의로 미확정을 없애지 않는다. |
| 필수 상대 패치 누락 | 제목·본문 등 함께 바뀌어야 하는 패치가 누락되거나 겹치면 묶음 전체의 적용을 중단한다. 완전하고 충돌 없는 묶음과 전체 후보로 다시 검사한다. |
| 길이·출력 한계 | 임의 길이 상한은 두지 않는다. 실행 환경 한도로 전체 기사나 근거를 읽지 못하거나 완성문이 잘리면 완료·안전한 전달로 세지 않는다. 전체 입력과 출력이 가능한 조건에서 재개하며 요약·해시·후속 도구 지시로 전문을 대신하지 않는다. |
| 수신 확인·식별자 실패 | 입력/출처/패치 ID의 공백·중복·오연결, 완성문/매핑/해시 불일치, 명령 실패, 비어 있거나 불완전한 수신 확인이 있으면 완료 처리하지 않는다. 성공 종료와 올바른 기사·완성문에 결합된 확인을 다시 검사한다. 파일이 존재한다는 이유만으로 전달 성공이라 하지 않는다. |
| 새 의미 손실 | 귀속·반론·발언 강도·조건·책임·시간 관계가 변했는데 근거 있는 필수 수정으로 설명되지 않으면 해당 변경을 철회하거나 안전한 대안을 재검사한다. 남은 손실을 수정 성공과 상계하지 않는다. |

수신 확인 파일과 결과 파일이 항상 함께 완성되는 두 파일 트랜잭션은 보장되지 않는다. I/O 실패 뒤의 부분 신규 출력은 전달 완료로 취급하지 않는다. 원본과 동결 판단은 보존하고 실패 후보와 재개 이유를 구분해 남긴다. `ready`는 주어진 작업·확보 근거 범위에서의 준비 상태이며 공개 승인이나 전체 기사 무결함 선언이 아니다.
