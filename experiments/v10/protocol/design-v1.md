# Journal v10 — 한 회차 통합 개선 및 분리 검증

고정 시각: 2026-10-01 22:37 UTC (이 문서는 결과 관측 전에 작성한 운영 설계; 아래 입력 파일은 별도 해시 manifest로 동결).
종료 상한: 2026-10-02 00:30 UTC. 00:15 이후 신규 실험을 시작하지 않고 집계·보고 저장. 주간 사용량은 확인 불가하며 잔여량 보장하지 않는다.

## 질문과 범위
1. 원문에서 추출한 보호목록 밖의 누락을 원문 재독립검토로 찾을 수 있는가?
2. 실제 적용/보류/원복 상태에 연결한 최소 patch 및 전달 주석이 v9의 설명 모순을 막는가?
3. 평가의 주장 단위와 질문 범위를 고정하면 판정 차이를 어떻게 분리할 수 있는가?

기존 v8/v9, 원평가, 원출력은 보존한다. 그 사례는 회귀용이며 미사용 holdout이 아니다. 이번 새 원문은 준비 단계에서 연구자가 열람한 소규모 전이 사례이며 무작위 표본이 아니다. 합성 최소쌍은 실제 사건 성능과 분리한다. 기사 전문은 private 폴더에서만 보존한다.

## 독립 역할과 실험 크기
보호목록/누락탐지, 최소편집/롤백 구현, 평가기준/최소쌍 설계의 세 작업을 fresh-context agent로 병렬 수행한다. 최종 작성자와 독립 평가자는 원문·같은 근거·같은 질문·기준을 받는다. 보호목록은 참고이며 gold가 아니다. 평가자는 후보 작성 과정과 조건 라벨을 받지 않는다. 원문 재독해로 체크리스트 밖의 손실을 찾도록 한다.

최대 입력 묶음: 기존 실제 회귀 2건, 신규 실제 원문 1건, KO/EN 합성 최소쌍 6쌍(12입력). 묶음 간 반복/번역/최소쌍을 독립 사건으로 세지 않는다. 각 입력에 실제 native writer의 새 응답을 기록하고 두 fresh-context 평가자의 원응답을 보존한다. 엔진 fixture 출력은 deterministic output으로 별도 집계하며 모델 생성으로 세지 않는다. 실패를 보고 후보를 수정하면 원본/수정본을 별도버전으로 남기며 새 holdout이라고 부르지 않는다.

## 개선 절차
원문 전체/접근 범위와 해시 → 근거 위치가 있는 보호표(주체·수치·대상·조건·부정·발언 강도·반론대상·사건/발표/후속 시점·비교 모집단/지표) → 원문 재독립 누락감사 → 근거가 있는 오류만 span patch → 의존성 묶음 검사 → 수정부분 근거검사와 원문 의미 보존검사 → 불확실/새 오류에는 수정 보류 또는 의존 묶음 원복 → 최종 bytes/hash 및 실제 적용 상태에서 전달 주석 생성.
발언이 틀린지와 발언자가 그렇게 말했는지 분리한다. 원발언 내용을 조용히 바꾸지 않는다. 후속 관측이 앞선 예측/기록을 반박하는지는 지표·대상·시점이 같은지 확인한다. 본문과 검사 주석의 길이는 구분한다. 길이 제약에 보호정보를 담을 수 없으면 삭제 대신 길이 증가 필요를 표시한다.

## 사전 평가 원칙
중대한 사실/귀속/범위/시간/비판 손실은 개선 성공이 아니다. 근거 부족은 unknown/hold로 남긴다. 단순 no-op은 불필요한 변경 방지 성공일 수 있어도 오류 해결 성공과 별개다. 특정 수정 목표 해결과 전체 기사 검증을 구분한다. 원래 오류가 남았는지, 새로 오류가 생겼는지, 전달 설명이 실제 변경과 맞는지를 각각 판정한다. 자동 기계 검사는 바이트·해시·상태 일관성만 증명한다. AI 합의/자신감은 진실의 정답이 아니다. 반대뿐 아니라 합의 수용 후보도 원근거에 대조한다.

정확한 배포 모델 버전/seed/토큰비용은 미제공. 모델 override 없이 현재 runtime의 fresh agent를 사용하되 독립 모델 계열 또는 인간 검증으로 부르지 않는다. 총소요시간은 기록된 UTC 기준 경과시간이며 활성 계산시간/유료비용으로 바꾸지 않는다. 새 유료 API, 외부권한, 계정변경, Git push/merge/배포를 하지 않는다. 결과는 기존과 구분한 새 Library 보고서로 저장한다.
