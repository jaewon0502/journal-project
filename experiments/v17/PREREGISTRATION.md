# v17 사전등록 동결본

2026-10-03. 평가 생성 전 동결. 실제 자료4건(KR2/EN2), 후보8개, 사전 독립 AI 참조 defect4/normal4, 두 방법16출력 예정. 출력을 보기 전 기준과 분모를 고정했다. 개발 v1 실제8출력 중7개는 출처 ID와 위치 설명 혼합으로 계약 검사 실패였다. 원출력 보존, 공통 지시에 exact source ID 규칙만 추가하고 노출2단위×두 방법4출력 재검증에서 형식 오류0을 확인했다. 이는 새 접근이나 새 사례가 아니다.

수집 결과는 정부 정책기자단·기관 뉴스4건이며 독립 언론4건이 아니다. 실제 정상 대조는 원문과 동일3개와 원문 오류를 근거로 정정한1개다. 당초 정상 어순 변형 계획은 이번에 실행하지 않았으며 평가 후 바꾼 것이 아니다. 기사들은 분야가 다르지만 원자료와 기관 계보가 공유되므로 독립증거 수를 기사 수로 부풀리지 않는다. 기본 산출물에는 임의 길이 제한이 없다. 아래의 계획·규칙은 이 실제 확정 범위로 시행한다. 정확한 입력·지시·구현·참조·일정 해시는 비공개 동결 명세에 있다.

## Question and decision criterion, specified before inputs or outcomes

Does a bounded source-clause witness check improve necessary source-condition repair over the same-evidence minimal-patch procedure, without increasing unnecessary edits, local holds or new losses? LINK adds one explicit process instruction: inspect directly linked definitions/exceptions/scope/timing of a relied-on source clause. It receives no extra retrieved facts, highlighted links, answer key, alignment table or additional calls. Both arms have the same witness fields. This is a bounded source-witness ablation of earlier source-first/minimal-patch work, not a new reasoning principle, complete source inventory or ten distinct failed approaches. Earlier v10/v12/v13 work already used source anchors/evidence IDs, adjacent-context checks and clause dispositions; those components are not new here. The sole narrow manipulation is the explicit bounded linked-clause tracing instruction.

Limited positive signal requires LINK to achieve at least one additional correct necessary repair on pre-reference-confirmed condition-loss units, no losses of BASE's correct repairs, and no increases in false mandatory claims, unnecessary patches, unjustified local holds, or audit-confirmed new losses on any confirmed eligible units. Report detection separately: improved detection without an additional safe repair is detection-only evidence, not primary success. If paired correct repair outcomes are equal and no harms increase, report no observed repair benefit. If LINK loses a BASE repair or introduces any confirmed additional harm, the harmless-improvement criterion fails on this sample; identify tradeoffs, do not hide them in a composite. A tie is no observed benefit, not evidence that either method failed. If BASE is perfect, retain the planned inputs and report the ceiling; do not manufacture harder evaluation inputs after viewing outcomes. Missing/invalid outputs, ambiguous pre-reference or unresolved audit safety make the relevant comparison unknown; unknowns cannot establish harmlessness. No observed improvement does not prove general ineffectiveness, and 4 articles cannot establish equivalence or general safety. No aggregate political-bias, trust, news quality or overall alignment metric will be calculated.

## Stages and separation

1. Develop on two new synthetic contexts, each with one condition-loss candidate and one complex correct countercontrol: 4 units x 2 arms = 8 planned writer outputs per development round. Use one fresh native call per unit/arm. Keep development outcomes outside confirmatory counts; log every revision and every call. If more rounds are necessary, count them rather than call them new contexts. These data may change the procedure only before freeze.
2. Independently collect 4 new full articles, KR2 and EN2, plus directly relevant primary documents. New means not an article/event used in prior v12–v16 evaluation or synthetic development; check the existing source manifests. Do not select articles using observed method outcomes. Record headline/subtitle/body/captions acquisition, document versions, dates, official URLs, read/excluded scope and hashes. Prefer sources applicable at the article's date. Missing final or historical versions remain explicit gaps; do not substitute a draft and claim final-law verification.
3. Each article yields one researcher-created source-condition-loss candidate and one complex normal countercontrol: 8 evaluation units x 2 arms = 16 planned writer outputs. Construct all candidates and Q before methods run. A loss must affect a supported condition, not just delete arbitrary detail. A countercontrol must retain multiple interacting semantic features (e.g., distinct subjects, times, scope restrictions, attribution, criticism or uncertainty); length alone is insufficient. No arbitrary length cutoff or compression constraint. Use two unchanged controls and two meaning-preserving surface-reordered controls if source material supports this without ambiguity; freeze actual choices. Preserve complete candidate text. Article original errors are never silently normalized: log candidate construction/corrections and judge them separately.
4. A fresh pre-AI reference reviewer reads each unit's complete O/C/S/Q before any evaluation method writer is called, without arm instructions, author expectation, variant label, other candidate or pair map. Freeze atomic questions, condition anchors, necessity, expected safe minimal repair if supportable, normal/defect/uncertain classification, known inherited issues and coverage/version uncertainty. No writer response or diagnostic snippets may reach this reviewer. No outputs exist yet. Freeze the reference records and evaluation manifest. Construction author intent is not gold. A reviewer who has seen the paired units is not strictly pair-blind: log exposure and restrict claims. Prefer fresh per-unit contexts to avoid pair recognition.
5. If a candidate's intended target is ambiguous, before evaluation either revise and obtain a fresh reference or retain it explicitly as uncertain; record all revisions/exclusions and lock final denominators. Do not replace inputs after seeing writer outcomes. A failure to obtain four suitable full-article pairs is a feasibility shortfall, not permission to fabricate sources or report planned n as completed.
6. Run each unit once per arm in a fresh native context using the same deployment/settings exposed by the platform, tool access, shared schema and common instructions. Both get byte-identical O/C/S/Q/source metadata. Only basemethod.md vs linkmethod.md changes. Do not share memory or the sibling response; no feedback/retry for semantic mistakes. Randomize within-pair arm order and unit order using a recorded scheduling seed; this is not a model seed. Provider failures/retries must be logged, with failed attempts preserved. If settings or snapshot are not exposed, report unknown, never pretend exact reproducibility. Freeze any system wrapper and verify that it is identical between arms.
7. Validate output schema and patch contracts, then mechanically apply exact, uniquely occurring, nonoverlapping before spans against the frozen candidate. Do not repair the method's JSON or patch text silently. Dependency closure must be satisfied. Preserve raw output, proposed patches, application/rejection logs, actual applied candidate, and hashes. Technical invalidity H-X is reported in the full flow and counts as no delivered repair, with semantic status unknown where appropriate. Never silently remove invalid outputs from denominators.
8. In fresh contexts, condition-blind post-auditors read complete O/C/S/Q and the full actual applied candidate plus anonymized patch/findings. They do not see condition names, paired responses or author expectations. First independently judge the candidate; compare with frozen pre-reference only afterward. Patch wording may suggest a method, so do not claim perfect blinding. Audit full text including untouched parts for new errors, lost source conditions, attribution/criticism/uncertainty changes and interactions. A diff or writer self-check alone is not an audit. Freeze first audits. Later corrections/rollbacks are reported as adaptive follow-up and cannot replace first-pass outcomes.

## Shared semantics and schema contract

v17-common.md is authoritative and schema.json is shared. required_answer_missing means no answer to an atomic Q part; answer_present_but_incorrect means a supplied but false answer. They cannot both be yes for the same atomic question. A broad false answer caused by deleting an exception may have factual_error=yes, conclusion_changing_omission=yes and original_meaning_loss=yes; answer_present_but_incorrect=yes, required_answer_missing=no. Empty answers and false answers must not be conflated. Optional clarification and a necessary omission cannot both be yes for the same detail. Multiple flags otherwise may overlap with separate anchored propositions. Inherited/source-only errors are not edits' original-meaning losses.

Necessity requires a concrete Q-answer/scope/attribution/force difference under the actual complete context, not general value or usefulness. Opinion disagreement is not a factual correction. Pre-reference and post-audit disagreement is retained field by field; report original judgments and any later adjudication separately, never retroactively force consensus or replace denominators. Humans participating: count actual people; AI references are not human ground truth.

Schema validation is structural; the checker must additionally validate unique IDs and references, exact anchor presence in identified documents, all four patch gates yes, no overlap, dependencies, atomic-question field consistency and aggregate preservation_decision. A valid JSON object alone is not a safe patch. Unique patch application is against original C offsets, with replacements applied in descending position order. Empty before strings are invalid. Content findings are semantic audit tasks, not just string checks.

## Endpoints and denominators

Freeze n=4 intended unique articles (KR2/EN2), n=8 intended units, n=16 intended outputs; report completed, invalid, missing and uncertain separately. Four within-article candidate pairs are correlated, and two arms on one unit are paired, not independent articles. Present every unit and article's paired result, and language strata descriptively; no population significance or bias-reduction estimate.

- Detection: exact grounded identification of the pre-reference-confirmed missing condition / confirmed condition-loss units. Generic suspicion or hold is not detection; supported detection with unsafe correction held may count for detection alone.
- Repair: correct necessary correction actually delivered and confirmed safe by full-candidate audit / pre-reference-confirmed condition-loss units. Report missed, incorrect, held, invalid and unknown separately. Detection and repair are not interchangeable.
- Controls: no-change retention, false mandatory claims, unnecessary patches, unjustified local holds and preserved criticism/attribution / pre-reference-confirmed normal controls. A normal control is normal in the defined source-condition/minimal-edit task, not globally fact-certified. Separate justified inherited-issue repairs from false positives; if such repairs make the intended no-change control inappropriate, classify it before writers rather than retrospectively excusing changes.
- Safety: confirmed new semantic harms / applied outputs with determinate full audit, plus unknown audit count and total applied outputs. Also report patch-level harms and total applied patches so multiple patches do not masquerade as independent units. If no patches are applied, safety rate is NA, not zero. Report conservative bound (confirmed unsafe + audit unknown)/all applied outputs beside the determinate ratio.
- Delivery: safe required corrections actually applied / corrections pre-reference establishes necessary and safely supported. Do not imply success by withholding everything. Different but equally correct minimal repairs are allowed; exact wording is not gold.
- Scope: local holds by H-E/H-N/H-S/H-D/H-X, unrelated coverage gaps H-C, remaining inherited errors, whole-candidate safety and overall readiness separately. An unrelated coverage unknown is not an unnecessary local hold; local success is not publication readiness.
- Overhead: actual writer call count, all reference/audit/development/retry calls separately, full rendered input Unicode-character count and raw-output Unicode-character count per output and arm, with UTF-8 bytes if useful. Include shared schema/system wrapper in input counts when accessible, and state excluded inaccessible overhead. Report paired differences and totals. If available, log coordinator-observed phase start/end times and wall duration, explicitly including orchestration/wait overhead and not calling this model latency. Native token counts, deployment version, model seed, latency and money are unknown unless actually exposed. Characters are not exact tokens or cost. No claim of lower overhead solely from shorter instruction text.

## Natural errors, induced errors and limits

The planned loss variants are researcher-induced errors in real-article contexts; countercontrols are constructed controls. Naturally present article errors, if discovered, are separately labeled exploratory inherited findings, with discovery time and initial evidence. Do not count them as successful induced-target repairs or infer natural-error prevalence. Synthetic development, v16 exposed-law regression, evaluation articles, adaptive follow-up and any natural errors each have separate ledgers. Whole source verification, general omission completeness and AI-judge reliability remain open even if this test succeeds. Publish only source metadata, hashes, short permitted evidence and aggregate/field-level outputs cleared of full article text; full articles/candidates/raw outputs remain private.
