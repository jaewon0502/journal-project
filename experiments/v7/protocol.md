# 연구 방법: T 최소편집과 J 근거 개입

이 문서는 완료된 실험의 공개용 방법 설명이다. 내부 실행 지시문이나 원래 프롬프트 원문은 포함하지 않는다.

## T

개발 2사건, 고정 평가 4사건에서 사건마다 정상·동등·단일관계 오류 변이를 만들었다. 공식 원자료는 실제 사건 자료지만 답변과 오류는 AI가 작성한 합성 통제다. 공통 탐지에서 오류 위치와 유형·슬롯을 추출하고 별도 문맥의 원문 감사에서 오류 사실·UTF-8 수정 범위·유형 적합성·원문 구간의 문맥 적합성을 확인했다.

세 방법은 같은 초기 답변·질문·원자료·탐지·승인 범위를 받았다. 자유 최소편집은 승인된 절만 모델이 고쳤다. 유형 렌더러는 승인된 슬롯을 결정론적 문장으로 조립했다. 원문 구간 삽입은 정확한 연속 구간을 수정 없이 삽입하되 주변 문맥에 맞을 때만 허용했다. 정상·동등 답변은 공통 상류 감사가 no-op을 승인하면 그대로 반환했다. 세 방법의 독립 전체 파이프라인 또는 동일 비용 비교가 아니다.

패치 검사는 수정 전 해시·before 바이트·UTF-8 경계·허용 범위·변경 밖 동일성을 확인했다. 허용하지 않은 수정이나 실패는 원문으로 롤백했다. 보류·롤백으로 기존 오류가 남으면 복구 성공이 아니다.

최종 AI 평가는 방법명과 변이 종류를 가리고 질문·원자료·수정 전후 답변을 검사했다. 동일 문자열 출력은 한 번 판정하고 여러 방법에 연결했다. 복구는 오류 수정, 수정문 원문 지지, 질문에 필요한 의미 보존, 새 사실 오류 없음의 네 조건이 모두 필요하다. 정상·동등 보존은 바이트 동일성과 원문 지지가 필요하다. 기계적 범위 검사는 의미 판정과 별도다.

초기 6유형에서 개발 오류 둘 모두 유형 미지원이었다. 개발에서 한 번만 속보/확정 상태값과 보호 유지/제거 유형을 추가해 같은 개발 사건으로 재검증했다. 2026-10-01 04:53:35 UTC에 평가 버전을 동결했고 평가 실패를 보고 새 유형이나 범위를 추가하지 않았다. 개발 재검증을 새로운 일반화 증거로 세지 않는다.

## J

같은 주장에 원래 근거 packet, 유일한 지지 구간을 삭제한 packet, 동일 UTF-8 바이트 수의 무관 구간을 삭제한 packet을 각각 독립 문맥으로 제시했다. 기대 패턴은 지지 / 근거 부족 / 지지다. 인용이 입력의 연속 부분문자열인지 기계 확인했으나 문자열 존재는 의미 지지와 동일하지 않다.

초기 DEV02는 packet에 없는 구체성을 주장이 요구하는 결함이 뒤늦게 드러났다. 원본 가지 1회 판정 후 나머지 두 가지는 미실행했고 해당 판정은 유효 성공에서 제외했다. 수정한 packet의 별도 개발 회귀 3회는 기존 사건 재검증이다. 평가 packet 4개 중 3개도 첫 판정 전에 사전감사로 수정·동결했다. J는 개발 7회와 평가 12회, 총 19회 실제 판단이었다.

## 해석 제한

독립 문맥은 다른 모델 계열이나 인간 평가를 뜻하지 않는다. 원문 의미 전체의 누락 없는 목록, 평가자 간 재현성, 원문 밖 검색의 완전성은 입증되지 않았다. J의 삭제 흔적·표면 차이도 판정 단서가 될 수 있다. 사건·대조문·방법 출력·고유 판정·모델 실행 수를 혼합하지 않는다. 예비 M0/M1/M2와 한국어 렌더러는 미실행이므로 성과에 포함하지 않는다.
