# 같은 개선 점수에서 편집자가 인용한 근거 대조하기

두 가상 기사에서 편집자 두 명이 ‘표현과 발언 귀속’의 점수를 원본 2점, 수정본 0점으로 기록했다. 기사별 공동 개선은 각각 1/1이다. 기사와 설문 응답, 편집자 메모는 모두 이 예시를 위해 작성했다. 다른 편향 기준과 구절별 사실 여부는 평가하지 않았다.

| 기사 | 편집자가 대조한 내용 | 예상 결과 |
| --- | --- | --- |
| 여울시장 매출 설문 | 두 사람 모두 상인 12명의 매출 감소 응답을 같은 설문 행에서 확인했다. 원본에는 “엄살을 부렸다”, 수정본에는 “줄었다고 답했다”가 나온다. | 편집자 둘이 두 판본에서 같은 기사 구절과 설문 행을 인용했다. |
| 온들시장 공사 설문 | 한 사람은 상인 6명의 휴업 사유와 “핑계”라는 표현을 대조했다. 다른 사람은 주민 8명의 이사 의향과 “엄살”이라는 표현을 대조했다. 각자 수정본에서도 같은 설문을 인용했다. | 두 편집자가 인용한 기사 구절과 설문, 응답 집단이 서로 다르다. |

## 화면에서 확인하기

파일 선택 없이 결과와 인용문을 읽으려면 [오프라인 미리보기](preview.html)를 연다. 아래 방법으로 같은 결과를 도구에서 다시 확인할 수 있다.

1. [여러 기사의 수정 결과](../../docs/reader/revision-series.html)에서 두 기사의 공개 요약을 함께 선택한다. 공동 개선은 2/2다. [여울시장 요약](aligned-summary.json) · [온들시장 요약](different-summary.json)
2. 같은 화면의 진행자용 파일 입력에서 두 기록을 함께 선택한다. 공동 개선 2건 중 근거 위치가 일치하는 사례 1건, 다른 사례 1건이 나온다. [여울시장 진행자용 기록](aligned-case.json) · [온들시장 진행자용 기록](different-case.json)
3. 어느 문장을 골랐는지 읽으려면 [기사 평가 비교](../../docs/reader/article-compare.html#blind-revision)의 ‘돌아온 평가 비교’에서 해당 기사의 `*-case.json` 한 개를 연다. 이 진행자용 파일에 기사 두 판본과 설문 발췌, 편집자별 인용·판정 이유, 배정 대응표가 들어 있다.

## 재현

저장소 루트에서 `node experiments/bias-citation-audit/replay.cjs --check`를 실행한다. 예시를 현재 판정 도구로 다시 만들고 JSON 네 개와 미리보기가 저장된 내용과 바이트 단위로 같은지 검사한다. 각 기사의 진행자용 기록을 별도로 연 결과와 두 기록을 함께 연 집계도 검사한다. `--check`를 빼면 다섯 파일을 다시 쓴다.
