## Selected hypothesis

**Giving the existing editor a source-published entity/measurement key and its original schema context will reduce false numeric contradictions due to merged referents, compared with the same prose evidence alone, without reducing detection of same-key wrong values.** Use one narrow public dataset/registry/table domain where the publisher actually provides those keys. This is an evidence-acquisition intervention; keep editor policy, model, and repair permissions fixed. No further semantic gate, self-verification call, majority vote, source-first staging, or invented ontology is the treatment.

The new input must be an independently existing source artifact: e.g. publisher's stable object identifier plus measurement/series identifier, complete row/column headers and qualifiers, and a publisher-authored alias or parent/child relation where needed. The artifact must predate our case construction and be retrievable at its public URL. A source-maintained code distinguishes objects or measurement series; a newly generated UUID, extractor's object label, or AI-written same_entity=true does not. Different keys need source schema semantics: identifiers can be aliases or successive versions, and inequality alone is not proof of different referents. Equality of the parent project ID also does not establish equality of nested plot and system. Preserve publication/version/time fields so that a changed observation is not mistaken for a contradiction.

The procedure is feasible with downloaded HTML/CSV/JSON and Python's standard library. Follow a literal source link, dataset code, catalogue identifier, or documented publisher alias to retrieve the record. Keep the raw record and schema, then render the selected record with its native labels. The model still performs ordinary claim-to-record interpretation. Code can perform exact lookup after an observed identifier is selected; it cannot infer that an unlinked phrase denotes that identifier. When the article has no literal key, stable link, or publisher-authored bridge, report unresolved claim-to-key resolution. Adding the same model's guessed bridge would return to the prior approach.

A cross-document relation witness is a second admissible form of the same evidence hypothesis: a source explicitly states that named plot P is contained in installation S, or that label X is the documented alias for record Y. This can resolve a previously missing relationship. Two articles paraphrasing the same release are not independent corroboration; record their source lineage. A new document may contain new relevant information even from the same institution, but do not describe it as an independent authority merely because the URL differs.

## Primary methods actually inspected

### FEVEROUS — structured evidence keeps the context that gives a cell its meaning

Rami Aly et al., *FEVEROUS: Fact Extraction and VERification Over Unstructured and Structured information* (2021). [Full primary PDF](https://arxiv.org/pdf/2106.05707), [paper record](https://arxiv.org/abs/2106.05707). Read complete §3 task/data definition, PDF pp. 3–4 (local text lines 169–200), and complete §4 Baseline Model, p. 8 (lines 436–465); inspected §5.1 evidence evaluation as well.

The evidence units are sentences and table cells. Each has page/section context; cells additionally retain adjacent row and column headers, including multi-level headers, and hyperlinks. Context is distinguished from selected evidence. The baseline finds pages through entity matching supplemented by TF-IDF, ranks sentences/tables, selects cells with a trained RoBERTa model, and predicts verdicts from evidence plus context. This supports retaining a publisher's complete table coordinates and header hierarchy, rather than comparing isolated numbers. It does not prove that article entities were correctly linked, or that a Wikipedia cell is an authoritative registry record. Its trained baseline is not being reproduced here. The proposal borrows the evidence representation, not its numerical results or model.

### DWIE — entity identity and relations are different predictions

Klim Zaporojets et al., *DWIE: an entity-centric dataset for multi-task document-level information extraction*. [Full primary PDF](https://arxiv.org/pdf/2009.12626), [paper record](https://arxiv.org/abs/2009.12626). Read §3 annotation process at PDF p. 7; complete §4.2.2 Coreference Module, pp. 14–15, §4.2.3 Relation Module, pp. 15–16, and §4.3 Decoding and Prediction, p. 17; inspected §7 limitations at p. 26. Local anchors: lines 397–407, 821–913, 967–985, 1517–1525.

The dataset clusters mentions into entities, annotates relations between entities, and links clusters to Wikipedia. The trained model scores antecedent pairs for coreference separately from directional relation pairs, then decodes mention predictions into entity clusters and cluster relations. A containment relation therefore need not imply identity. Crucially, the paper's implemented joint model covers NER/coreference/relations; adding an entity-linking model is future work. Coreference annotations omit nominal and anaphoric expressions. Thus it cannot be presented as a ready, validated solution for phrases such as “the crop area” and “the installation,” nor as evidence that external identifiers improve this editing task. Deploying it would require its trained weights/software and domain coverage assessment. The low-cost proposal uses publisher-provided relations, not this learned pipeline.

### FinQA — correct arithmetic cannot recover missing table identity

Zhiyu Chen et al., *FinQA: A Dataset of Numerical Reasoning over Financial Data* (2021). [Full primary PDF](https://arxiv.org/pdf/2109.00122), [paper record](https://arxiv.org/abs/2109.00122). Read complete §5.1 FinQANet Framework, PDF pp. 5–6, local lines 286–399; §3 task/representation at p. 3; Appendix C Figure 5 and its explanation at p. 13, lines 775–792.

FinQANet retrieves facts by linearizing table rows with header context, then generates an executable program from input values/row names, DSL operations, and intermediate-step memory. Program generation still depends on selecting the right operands. Appendix C Figure 5 reports a failure where the row-based representation obscures whether repeated row names belong to 2013 or 2014; the authors point to full-table context as necessary. This is a direct method-level reason to preserve source-native observation coordinates, beyond arithmetic validation. It is a numerical QA paper rather than an entity-resolution guarantee or a full claim-verification method. Running its trained retriever/generator would require model artifacts and dependencies, which the selected intervention avoids.

## Minimal falsifiable test to preregister elsewhere

Use naturally sourced cases whose entity/series codes and schema are public. Freeze evidence acquisition and claim-to-key mappings before any outcome; preserve the raw publisher record so these mappings can be independently checked. Both conditions receive the identical article and baseline prose, use identical policy and calls, and differ only in the genuine publisher key/context/witness. Include different-object valid numbers, same-object wrong numbers, correct same-object values, and unresolved mappings. The key/context may supply information, so an improvement estimates the benefit of acquired evidence, not superior reasoning at equal information. If it only restates existing evidence, label the test as representation rather than information acquisition.

Score false contradiction edits, missed true errors, normal-text preservation, and unresolved mappings separately. A gain caused solely by withholding all numeric edits fails the hypothesis. Separate literal-key cases from semantic-bridge cases; pooled success would conceal the remaining coreference problem. Do not choose cases after seeing which condition wins. This document executes none of these tests and makes no performance claim.

## Exact inputs and blockers

For a no-new-model implementation, each case needs the complete article, its source URL, a public publisher record with a stable entity key **and** metric/observation context, schema definitions, and an explicit bridge from the article mention/link to that key. A downloaded snapshot with content hash and original URL suffices; neither paid API access nor credentials are inherently required. Public access for a specific candidate must still be confirmed. Ordinary country/company IDs alone are insufficient when the ambiguity concerns a nested area, denominator, treatment, or time series.

For the exposed v23 agrivoltaic case, DOI 10.1016/j.xcrp.2026.103555 identifies a paper, not the crop plot or PV footprint. The needed input remains its layout/methods/figure/supplement explicitly connecting the measured crop area, system area and treatment identifiers. No new access attempt was made here and no such relation was recovered. An external company/geographic registry would not resolve that missing within-experiment relation. The known case therefore remains blocked for a source-native resolution test until that exact source content is available.

If nominal mention resolution must be automated without literal bridges, an independently trained coreference/entity-linking model with applicable entity inventory or independently supplied human/source annotations is needed. None was downloaded or run. Even such a model remains fallible; using it would test a different intervention and add model/dependency costs. The selected low-cost hypothesis deliberately stays within documented literal links and publisher-authored relations.

## Final narrowed candidate from parent: native table image versus extracted text

The parent supplied a more immediately executable contrast after this research: KO BOK GDP/GDI tables and EN TOI-715 b/TIC 271971130.02 Table 3. Their specific pages/images have not been inspected by this literature agent; final eligibility depends on the parent's source and image confirmation. This **supersedes the evidence-acquisition hypothesis above for the proposed immediate trial**.

**Hypothesis:** adding a legible rendering of the publisher's original table page to the identical complete source text reduces mistaken row/column/qualifier binding in numeric comparisons, relative to extracted text alone, while preserving valid claims and retaining corrections of genuinely wrong values. This tests access to spatial representation of already supplied evidence. It does not test newly acquired independent facts, external semantic supervision, or a more restrictive edit policy.

Exact conditions to freeze:

- A: complete unchanged article + complete fixed source text extracted from the publisher PDF + common editor instructions.
- B: exactly A's article, text and instructions + the fixed publisher-page image containing the relevant table, original headers, caption and visible notes. Include the necessary adjacent page when a header, caption or note spans pages; document that scope before outcomes. No highlights, AI-authored alignment ledger, verdict labels, cropped-away rival rows, or treatment-only textual hints.
- Both: same runtime model/settings, call structure, output schema, edit permissions, numeric calculation options and available source facts. Do not add source-first staging or a new gate. Freeze the exact text and image files and hashes. Model access to images is part of the treatment; total input tokens and computation cannot be claimed equal merely because the text is identical.
- Use genuine publisher images, not an AI-redrawn table. Confirm legibility and preserve row labels, complete column hierarchy, units, comparison periods, fit assumptions and footnotes. If the extracted text omits facts visible in the image, the run mixes information recovery with spatial representation; disclose this and do not call it a pure layout-only effect. Conversely, if the extracted text already faithfully encodes those relations, B is a redundant visual presentation whose possible benefit remains an empirical question.

Method grounding is specific and limited. FEVEROUS §3 explicitly makes cell interpretation depend on row/column headers and title/section context, including complex headers; §4 supplies this context to the verdict predictor. FinQA §5.1 linearizes rows for retrieval, and Appendix C Figure 5 identifies loss of year disambiguation in row-based retrieval and the need for full-table context. Those methods justify testing whether native table presentation preserves semantic relations lost or obscured in extraction. **Neither paper establishes that adding raster images to this editor improves accuracy.** Their support is for contextual evidence representation, not a published visual-versus-text effect. DWIE contributes the conceptual distinction between referent identity and relations but is not direct evidence for this visual intervention.

Record wrong-referent edits, same-referent numeric error corrections, correct-clause preservation and unnecessary unresolved outcomes separately. Report image legibility/coverage and extraction quality as manipulation checks, not scored semantic successes. If the text already contains all facts but spreads headings and values across lines, a gain could reflect easier alignment/attention; it is not proof that the model has acquired authoritative object identity. Native table structure can remain ambiguous or the article-to-table mapping can still be wrong.
