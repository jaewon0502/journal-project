# v6 설계 파생 요약

이 문서는 실제 설계를 설명하는 공개용 재작성이다. 내부 실행 지시나 원래 프롬프트가 아니다.

- DEV 8사건 한 블록, EVAL 8사건씩 두 블록으로 실행했다. 각 사건은 질문 4개와 정상·동치·단일관계 변이 후보 3개를 계획했다.
- A0/A1은 동일하게 사전 취득·동결된 원자료 묶음에 접근했다. A1은 본문·렌더·표·첨부 점검을 명시했다. 최초 웹 수집 절차의 효과는 측정하지 않았다.
- D0는 기본 검사, D1은 같은 후보에 명시적 의미영향 관계표 점검을 추가했다. 재작성·수정 실험이 아니다.
- C0는 DEV D0에서 이어지는 재사용 문맥으로 정답·점수 피드백 없이 EVAL을 검사했다. C1은 EVAL D0의 새 문맥 출력을 공통 대조로 사용했다. 새 문맥 단위는 사건별이 아닌 실행 블록별이다.
- 실제 성능 실행은 DEV의 A0/A1/D0/D1 네 호출과 EVAL 각 블록 A0/A1/C0/D0/D1 다섯 호출씩이다. 준비·코드 테스트·모델 별칭 probe는 성능 호출에 포함하지 않는다.
- 개발 결과 이후 결정은 no_change였다. 최초 기준을 유지해 고정 EVAL을 한 번 실행했다. 후속 실험은 이 EVAL을 미사용 평가 자료로 취급할 수 없다.
- 분모에서 자료 미취득 사건, 부적격·미확정 대조문, 보류를 삭제하지 않는다. 유효성 없는 후보는 성공 분자에서 제외한다. 없는 후보는 모델이 판정한 것처럼 생성하지 않는다.
- DEV03 발표월 오류와 정상 문장 모호성, EVAL05에서 두 인과관계가 함께 변한 후보를 각각 부적격/미확정으로 남긴다.
- 의무별 preserved, partial, omitted, unverifiable를 구분한다. 주장의 supported와 partial도 구분한다. partial에 임의 분수 점수를 주지 않는다. 원자료 없는 사건의 severe 판정은 unknown이다.

원자료 묶음의 완전성, 의미검토 범위, 의무 목록의 완전성은 별개다. GDP 관계 반전은 고정 의무 보존 수치만으로 잡히지 않았다. 높은 보류율과 같은 계열 AI 간의 일치는 일반적인 안전성 근거가 아니다.
