# 어떤 자료가 먼저 열리는가

2026년 11월 24일 새로 작성한 가상 기록 두 묶음으로 문서 추천 순서를 평가한다. 한 묶음에는 한 사업의 계획, 중간 점검, 준공 실적이 있고, 다른 묶음에는 발언 속기록, 공개 일정표, 실제 게시 이력이 있다. 같은 사업을 다뤄도 확인하려는 질문에 따라 먼저 대조할 문서가 달라진다.

## 사전등록

입력·정답·측정 기준을 담은 `holdout.json`의 SHA-256은 `5b509ff0d910320f33806afca105bd2abf23ed84e33bef9c757f063173b7823c`이다. 이전·변경 엔진을 조회하기 전에 고정했다. 문서 발췌, 기관, 인물, 두 정당명은 모두 이번 실험을 위한 가상 설정이다. 참여자 연구 및 최종 측정팩에는 포함하지 않는다.

각 주장을 단독으로 `prepare()`에 입력하고 추천 목록 맨 앞 자료와 실제 기본 열림에 쓰는 자료를 확인한다. 확인할 원자료가 특정되는 6건, 사람이 추가 정보를 확인해야 하는 대조 사례 2건이다. 두 대조 사례에는 단일 정답 자료를 지정하지 않았다. 미측정 결과를 설명할 자료가 없는 경우와 질문에서 어느 시점을 뜻하는지 정하지 않은 경우가 각각 1건이다.

정답 6건 각각을 입력 순서 3가지, 정당 표기 3가지로 제시한다. 자료를 돌릴 때는 식별자도 입력 칸에 따라 다시 붙인다. 정당 표기는 무표기 및 동형의 가상 정당명 두 개다. 주지표는 아홉 조건 모두에서 올바른 자료를 첫 추천한 원주장의 비율이다. 기본 순서·무표기의 첫 추천과 전체 후보 포함 여부도 별도로 보고한다. 54개 제시는 6문항의 반복이므로 독립 문항 수로 합산하지 않는다.

실제 화면에서는 기본 순서의 문서 세 개를 자료 입력 양식으로 추가하고, 두 정당 표기의 각 문장을 연다. 문서 후보가 열리는 것과 편집자가 체크박스로 원자료를 골라 사실 판정을 저장하는 것은 구분해 관측한다.

## 최초 비교 결과

| 지표 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 9개 조건 모두 첫 추천이 정답인 원주장 | 4/6 | 6/6 |
| 기본 순서·무표기에서 첫 추천이 정답인 원주장 | 6/6 | 6/6 |
| 기본 순서·무표기에서 정답을 후보 중에 포함한 원주장 | 6/6 | 6/6 |
| 첫 추천이 정답인 반복 제시 | 47/54 | 54/54 |
| 두 정당명만 바꿨을 때 첫 추천이 달라진 쌍 | 0/24 | 0/24 |
| 특정할 정답이 없는 기본 사례에서 한 문서를 자동으로 펼침 | 2/2 | 2/2 |

계획 수량을 확인하는 p1에서 기준선은 한 가지 순서의 세 제시 모두에 준공 검사서를 먼저 추천했다. p4에서는 예정 게시일을 물었는데 순서와 정당 표기가 결합된 네 제시에서 실제 게시 기록을 먼저 추천했다. 수정 후에는 두 경우 모두 사전에 특정한 계획 문서가 먼저 나왔다. p4에서 두 가상 정당은 동일한 결과를 보였다. 양쪽 정당 표기 결과가 같더라도 무표기 결과까지 일치한다는 뜻은 아니다.

근거가 없거나 기준 시점이 불명확한 대조 사례에서는 두 버전 모두 반복 제시 18/18번에 복수 후보를 내고 한 문서를 자동으로 열었다. 사고가 감소했는지 물은 u1에서 기본으로 열린 문서는 기준선에서 중간 일지, 수정 후에는 준공 검사서였다. 두 문서 모두 보행사고 통계를 싣지 않았다. 양 버전 모두 첫 추천과 화면 열림에 쓰이는 자료 ID는 72/72번 일치했다.

`first.json`은 제시별 추천 문서와 기본 열림을 보관한다. SHA-256은 `7c21bb0d234c96293db38a3645f8212d3ef2c288fa5c4c4fc97b3981cdff99ee`이다. 공개 이후 같은 자료에서 얻은 성적은 재시험으로만 해석한다.

이 폴더에서 원 측정값을 재현하는 명령은 다음과 같다.

```sh
node score.cjs \
  snapshot/baseline.cjs 62ede658b6c2bc7758c10f2b49565ac612d0314d4e6029542e3b44c690bd9338 \
  snapshot/candidate.cjs b5c14dd7b19e70980d0271dac25449f9459f7ecf44b0b97d074310ae4236600f
```

## Chrome 첫 화면

기본 순서와 정당 표기 두 종류로 Chrome 157.0.8103.79에서 8문장을 각각 열었다. 16/16회 모두 문장 판단이 미선택이고, 원자료 체크 및 편집자 확인 체크는 비어 있었으며 인용 내용은 미확인 상태였다. 정답을 특정할 수 없는 두 대조 사례는 두 정당 표기 모두에서 자료가 하나씩 자동으로 열렸다(4/4회). 이 결과는 화면이 자료를 먼저 보여준다는 뜻이며, 해당 문서가 주장을 입증했다고 판단한 사람의 비율을 측정하지 않는다.

양 정당명의 첫 문서는 같았으나 기준 시점이 모호한 u2는 무표기에서 일정표, 정당명을 붙인 문장에서는 실제 게시 기록이 먼저 나왔다. 실제 화면 기록은 `ui-first.json`에 있다. 파일 SHA-256은 `a1a406cad5eb9a2fa4fdafd795f3688c368100c812bdcbf2ad8aa8a3426a039b`이다. 두 정당 표기에서 확인한 예가 실제 정치적 편향 감소율을 추정하기에는 부족하다.

## 공개 후 UI 재시험 절차

최초 결과가 공개된 뒤 같은 8문항에서 문서 순서 3개와 무표기·두 가상 정당 표기를 조합해 실제 Chrome 화면을 72회 관찰한다. 새 관찰기 `observe-ui-retest.cjs`를 사용한다. 정답 6건의 54개 제시에서는 올바른 문서의 기본 열림과 불필요한 경고를, 대조 2건의 18개 제시에서는 경고와 자동 열림 여부를 함께 센다. 각 화면에서 자료 선택, 판정값, 편집자 확인, 인용 내용 상태를 읽는다. 후보 목록 바로 위의 눈에 보이는 경고 문구를 원문 그대로 남기고 문서 단위와 반복 제시 수를 구분한다.

| 실제 화면에서 관찰한 결과 | 공개 후 동일 사례 재시험 |
| --- | ---: |
| 정답 있는 문장에서 지정 문서가 먼저 열림 | 54/54회 (6문장 모두 9/9) |
| 정답 있는 문장에서 경고가 표시됨 | 0/54회 |
| 근거 또는 기준 시점이 부족한 문장에서 경고를 띄우고 모든 자료를 접어 둠 | 18/18회 (2문장 모두 9/9) |
| 선택 자료·판정·편집자 확인·인용 내용 중 하나라도 자동 확인됨 | 0/72회 |

보행사고 감소를 주장한 문장에서는 변화량과 비교 기간을 확인할 원문을 찾으라는 안내가 9/9회 보였다. 기준 시점이 빠진 문장에서는 기사 작성자 또는 원자료에서 기준 시점을 확인하라는 안내가 9/9회 보였다. 두 가상 정당의 표기를 바꾼 경우에도 해당 경고가 유지됐다.

Chrome 157.0.8103.79의 [재시험 원기록](ui-post-disclosure-retest.json) SHA-256은 `516d1ac5c4485d6733201e3dee80dc41696af24abf8a5175610de82d9e9af42f`이다. 엔진은 `667aa23b2a9a9632cd22ec94b2ed8b851cee47d0461e977c81b1037798b633fb`, 화면 로직은 `1524f82e3580b44c6a42ad46f60e900a87b607ca06db80ddd8ebe979911eb037`을 사용했다. 경고 대상은 앞서 공개한 대조 문장이므로 새 기관이나 주장으로의 일반화는 이 관측으로 확인할 수 없다.

```sh
node observe-ui-retest.cjs ../../docs/reader \
  667aa23b2a9a9632cd22ec94b2ed8b851cee47d0461e977c81b1037798b633fb \
  1524f82e3580b44c6a42ad46f60e900a87b607ca06db80ddd8ebe979911eb037
```

브라우저 관찰기는 Node.js에서 Playwright를 불러오며 Google Chrome을 실행한다.
