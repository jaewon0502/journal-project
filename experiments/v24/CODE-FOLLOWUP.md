# 적용기 수정과 재검사 — 의미 성능과 분리

v1 동결 원실험의 결과는 바꾸지 않았다. 별도 코드 감사자는 사례/산출물을 읽지 않고 정확한 합성 반례로 네 유형을 찾았다.

| 결함 | v1 재현 | v2 처리 |
|---|---|---|
| 다른 절에 허용ID 재사용 | A 비교ID로 무관한 B를 수정 | 입력ID·원문해시·비교구간·숫자구간을 결합; 모든ID 확인 |
| 제한 없는 수정 후 문구 | 다른 수치/단위/추가 주장을 넣어도 허용 | 숫자 토큰1개만 허용값으로 치환, 나머지 문자는 동일하게 보존 |
| 계산 중 단위 무시 | 3m×3m를9m로 허용 | 피연산자 단위·차원 지수 계산; 덧셈/뺄셈 동일차원 요구 |
| 잘못된 스키마 처리 | 예외가 나고 명시적 차단 결과가 없음 | 점검한 잘못된 구조에 명시적 차단 결과; 원제안으로 대체하지 않음 |

독립 재감사가 같은 반례의 차단과 정상 수정·동등 단위·올바른 차원 계산을 확인했다. v2 단위검사20개 통과. 이 수는 기사 정확도20건이나 독립 접근20개가 아니다. v1코드 해시는 변하지 않았다.

## 실제 호환성/과잉차단

기존 비교장부에는 산술 피연산자 단위가 없었다. v2를 기존20제안에 그대로 적용하면 겹치는 집합의 올바른20→30명 수정이 양 조건에서 차단된다. **실제 오류5개 중1개 사례/출력2개를 자동 정정하지 못하는 회귀**다. 나머지 본문과 정상문은 그대로였다.

별도 AI가 원자료를 보고 관련 장부2파일의 피연산자4개에 count만 추가했다. 기존 값·관계·인용은 바뀌지 않았다. 보완 장부로 재생하면 기존20본문 모두 복원된다. 이것은 노출된 데이터의 스키마 보완/회귀이며 새로운 미사용 성능 개선으로 세지 않는다. 새 실행에는 피연산자 단위 필드가 필요하다. 숫자 외 단위/조건을 바꾸는 정당한 수정이나 복잡한 표현은 이 좁은 자동 적용기의 범위 밖이므로 검토필요로 남긴다.

## 남는 재현 반례

원문 A=2m, 근거 B=3m에 대해 AI가 대상의 동일성을 잘못 same으로 적고 실제 B 인용문을 붙이면, v2도 A의2→3 수정을 허용한다. 값·문자구간·단위 검사는 맞아도 A=B라는 의미가 틀렸다. 독립 재검사에서 이 주입 반례가 여전히 통과함을 확인했다. **실행 범위를 묶는 것과 출처가 같은 대상을 말함을 입증하는 것은 다르다.** 이번 자연 생성된 합성 산출물에서 같은 오류가 발생했다는 뜻은 아니다.

현재 쓸 수 있는 범위는 이미 근거 대조된 단일 수치의 엄격한 치환/복원이다. 새롭게 의미 신뢰도를 높였다는 근거는 없다. 근거 결합 불확실·복잡한 조건 변경·단위/시간 미지원·추정/범위/반올림은 자동으로 같은 비교라 가정하지 않고 보류한다.
