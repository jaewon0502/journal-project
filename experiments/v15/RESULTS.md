# Journal v15 — 필요한 부분만 수정하는 절차의 실제 검증

2026-10-03. 기존 원출력·원평가를 보존한 별도 AI 내부 실험이다. 세 갈래 연구(원문 보호목록, 최소 편집/의존성, 독립 평가)를 병렬 진행했다. **기계적인 편집·집계 결함은 고쳤고, 국소 정정의 안전성을 확인한 사례가 있다. 보호목록의 완전성과 수정 필요성 판단의 일반적 해결은 입증하지 못했다.**

## 실행과 비교 조건

- 합성: 12개 unit × 두 절차 = 실제 최종 판정 24행. 6개 생성 문맥이며 문맥당 4행이다. source-first 목록 4개는 별도 준비 산출물이다. 허구 자료이며 실제 기사 성능으로 세지 않는다.
- 신규 실제 자료: 한국어 전체 기사 2건, 원어 영어 전체 기사 2건 × 두 writer 절차 = 실제 후보 8개. 같은 사건의 두 후보는 독립 사건이 아니다.
- A는 임시 보호표를 먼저 읽고 원문·자료를 검사한다. B는 원문·자료에서 보호표를 작성해 해시 동결한 뒤 같은 임시표를 받는다. A/B는 이번 비교 이름이며 이전 단일/다기사 A-D의 이름과 의미가 다르다.
- 동일 기사·원자료·질문, 분량 상한 없음. B의 추가 단계와 순서가 함께 달라져 순수 순서 효과로 분리하지 못한다. 한국어 각 전체 본문·제목·부제·캡션을 편집 범위에 포함했다. 영어는 전체 본문 19문단이 편집 범위이고 제목·standfirst·캡션은 동일 입력 metadata로 읽고 변경 없이 별도 보존했다. 영어 제목/캡션 재작성 성능 시험은 아니다.
- 각 언어의 별도 검토자는 writer 표를 보지 않고 원문에서 자기 보호표를 먼저 동결하고, 후보 번호와 작성과정을 가렸지만, 첫 평가 파일의 patch ID에 A/B 라벨이 남은 문제가 후속 감사에서 발견됐다. 이 원평가는 완전한 조건가림으로 부르지 않으며 별도 새 문맥 재감사를 추가했다. 이 표도 gold가 아니다. 한국어 검토자는 필요성을 ‘식별 가능한 국소 문제에 비례하는 명료화’로 해석했다. 영어 판정과 엄격한 필수성의 단일 수치로 합치지 않았다.
- 기존 K01은 노출된 회귀 사례다. 기존 네 축 판정은 그대로 두고 P2/P5 관계만 두 새 문맥에서 평가했다. 새 미사용 평가가 아니다.
- 기본 native 실행 요청은 같은 상속 설정을 사용했다. 정확한 배포 버전·seed·token·비용은 제공되지 않았다. 합성 설계 감사 1건은 별도 요청 모델명으로 실행했지만 실제 deployment 검증/다른 계열 성능 비교는 아니다. 인간 참여 0명. 자동 API 대조실험으로 부르지 않는다.

## 작은 통제 실험의 결과

- 의존성 4쌍: 현재 수치를 고칠 때 정확한 과거 수치를 바꾸면 새 오류, 현재 합계가 깨지면 동시 정정 필요, 원래 있던 모순 잔존은 새 파손이 아님을 두 절차 모두 구분했다. 새 절차의 우월성은 확인되지 않았다.
- 보호목록 4개: 임시표가 놓친 핵심 4개를 source-first 목록이 포함했지만, 표 우선 조건도 원문을 읽어 같은 최종 판단에 도달했다. 목록 4/8→8/8은 구성된 작은 합성 입력의 내용 범위이며 최종 오류 검출 개선율이 아니다.
- 중요성 4쌍: 같은 자료라도 질문이 단체 예약 최소 인원을 물을 때만 그 조건이 필수 답이 된다. 원문에 있던 조건 삭제와 원문부터 없던 조건은 구별했다. 양쪽 최종 판정 동일.
- 전체 12개 비교에서 범주 필드 차이는 현재 합계를 명시해야 하는지 산술적으로 추론해도 되는지 1건이었다. 사전 기준이 이를 확정하지 않아 어느 쪽 오류로도 소급 채점하지 않았다. 조건 누락과 직접 논리모순을 같은 충돌 필드로 읽을 수 있는 문제도 남았다.

## 동일 후보 재평가에서 드러난 판정 문제

영어 2개 사건의 동일 4개 후보를 다른 새 문맥이 같은 원문·자료로 재평가했다. 독립 목록도 먼저 동결했다. 이는 새 기사 4건이 아니라 동일 출력에 대한 AI 재평가 4건이다.

- **E1: 필수성의 실제 이견.** 첫 감사는 A의 정정을 필요하다고 보고 B no-op를 보류했다. 두 번째는 A의 근거·안전성은 yes지만 필요성은 unknown이라고 판단했다. 원문의 주변 문맥이 효과·책임을 이미 한정하는지 해석이 달랐다. 따라서 첫 감사만으로 B의 확정 실패 또는 A의 검증된 개선이라고 결론내리지 않는다.
- **E1: gate 적용도 불일치.** 두 번째 감사는 필요성 unknown이면서 final accept를 냈다. 자동 적용 절차에서는 네 축 모두 yes가 필요하므로 이 요약 label을 그대로 채택할 수 없다. 원판정을 고치지 않고 별도의 보수적 적용 판정에서 이 변경은 보류한다.
- **E2: 승인 대상 범위 차이.** 두 감사 모두 추출 금지 patch의 네 축은 yes다. 첫 감사의 accept는 국소 수정 승인이고, 두 번째의 전체 hold는 원문 P011의 licence/consent 용어 잔존 때문이다. 이 둘을 같은 단위의 정반대 판정으로 집계하면 오류다.
- 두 번째 목록에는 source-only 배경을 partial로 기록한 항목이 있다. 이를 원문에서 새로 잃은 의미의 partial과 섞어 보존율 하락으로 세지 않았다. 목록의 분모/단위가 달라 보존율 직접 비교도 하지 않는다.

평가 불일치를 숨기거나 평균 점수로 없애지 않았다. 원문 오류 여부, 정정의 근거 지지, 정정 필요성, 개별 patch 적용, 전체 후보 공개 여부를 별도 축으로 기록해야 한다. 이번 결과는 평가 안정성을 해결했다는 증거가 아니라, 어디에서 불일치가 발생하는지 실제로 식별한 결과다.

## 코드에서 실제 고친 결함

1. 출력 파일이 receipt 경로와 같으면 기존 엔진이 성공 종료 후 결과를 receipt로 덮어썼다. 경로·alias 충돌 및 기존 파일을 쓰기 전에 거부하도록 고쳤다. 실제 CLI 20상황: 이전 9실패, 수정판 20통과. 파일 쌍의 원자적 저장을 보장하는 수정은 아니며 I/O 중단 때 새 불완전 파일이 남을 수 있다.
2. blind 목록 밖 judged ID를 기존 scorer가 집계했다. expected 집합·중복·누락·phase·mapping·비어 있지 않은 문자열 ID를 확인하고 오류 때 기존 결과를 보존한다. 수정판 15개 회귀 통과. 공개·접근 가능한 비공개 원기록에서 해당 결함의 기존 결과 영향은 발견되지 않았다.
3. 새 의존성 도구에서 누락 관계판정을 안전으로 취급한 결함과 겹치는 문자열 출현을 유일한 anchor로 잘못 승인한 결함을 개발 중 발견·수정했다. 모든 directed pair에 2명 판정이 필요하고, `aaa`의 `aa`처럼 위치가 두 개인 anchor는 거부한다. 현재 24개 합성 테스트 통과 및 독립 코드 재검토 완료.

기존 archive/result 검증을 포함한 전체 offline 검사에서 unittest 메서드 169개가 통과했다(그 안의 receipt 단일 테스트가 20 CLI상황을 순회하므로 169+20으로 더하지 않음). 원래 실행 산출물·점수는 보존했다. 테스트 통과가 미발견 결함이나 AI 의미 오류의 부재를 보장하지 않는다. 의존성 완전 대조는 patch n개에 2n(n−1)개 관계판정을 요구하여 비용이 커지며, 세 개 이상 수정의 결합 의미는 최종 전체 후보 감사가 별도로 필요하다.

## 조건 ID 누출 정정과 최종 보수적 재감사

후보 이름은 익명화했지만 첫 감사 입력의 patch ID에 A/B 문자가 남아 있었다. 작성 절차 대응표는 전달하지 않았으나 이를 완전한 조건가림이라고 부르지 않는다. 해당 8개 첫 판정과 영어 4개 재판정은 그대로 보존했다. 같은 원출력 8개에서 원본 patch ID·이유·writer 보호목록을 모두 제거하고, 허용 필드만 남긴 새 입력을 동결해 **새 문맥 2개에서 다시 8개 후보를 검사**했다. 절차명은 숨겼지만 실제 문체·편집 차이에서 조건을 추측할 가능성까지 제거한 것은 아니다. 새 기사나 새 writer 출력으로 세지 않는다.

|K15N|두 후보 무수정, 독립 목록 15항목 보존|당일 직접 자료 부족. 짧은 정상 후보 1건의 관측일 뿐.|
|K15Q|두 후보 모두 부제 P01 네 축 yes, 본문 P02는 필요성 unknown → P02 보류|원문 말미와 수정 부제가 이미 기간의 불확실성을 설명하므로 본문 명료화가 필수인지는 미정.|

K15Q는 승인 가능한 부제 P01만 실제로 적용하고 P02를 제외한 후보를 별도로 만들었다. 같은 독립 검토자가 이 실제 전체 후보를 재검사하여 새 손실·모순·귀속 오류가 없다고 확인했다. 본문 A02의 기존 압축 표현과 자료 부족은 남아 있으며 전체 준비도는 unknown이다. 이는 노출된 후보의 선택/회귀 검사이고 추가 writer 출력이나 새 holdout이 아니다.

새 감사의 보호목록은 E1/E2 각 본문 19개, K15N 15개, K15Q 17개 단위이며 첫 목록과 나눔 방식이 다르다. 이를 분모가 같은 점수처럼 비교하지 않는다. 전체 준비도는 원자료 검증 범위의 한계로 모두 unknown이었다. 이는 모든 기사가 틀렸다는 뜻도, 국소 수정이 해롭다는 뜻도 아니다. 확인된 오류, 미확인 주장, 필수성 유보를 구별한 판정이다.

라벨 누출을 막는 allowlist 코드와 합성 회귀 8개를 추가하고 별도 코드검토를 통과했다. 실제 저장 writer 출력 8개로도 텍스트 보존과 메타데이터 분리를 재생 확인했다. 새 감사 입력은 같은 원리로 수동 생성한 중립 ID 파일이며, 이 후속 코드가 이미 끝난 모델 실행을 생성했다고 주장하지 않는다.

## 실패 뒤 한 차례 추가 조사

E1은 공식 링크가 JavaScript 화면만 반환하던 한계를 정상적인 공개 XML 경로로 해결했다. [법원 제공 영문 전문](https://data.rechtspraak.nl/uitspraken/content?id=ECLI:NL:GHDHA:2024:2100)과 [네덜란드어 정본](https://data.rechtspraak.nl/uitspraken/content?id=ECLI:NL:GHDHA:2024:2099)을 2026-10-03 확보했다. 영문은 비공식 번역이라는 법원 고지를 보존했다. §§7.96–7.97·7.111은 특정 비율 의무의 근거 부족과 해당 명령의 실효성·청구이익을 독립 이유로 구분한다. P010 효과 설명은 §7.106에 대응하고 P009 청구 적법성은 §§6.8–6.9가 뒷받침한다. 문제 삼은 포괄적 표현의 정확한 위치는 P002다. 위치를 혼동하지 않도록 후속 기록에서 바로잡았다.

전문은 근거를 정밀하게 했지만 P002의 보완을 반드시 해야 하는지까지 자동 확정하지 않았다. 따라서 E1을 확정 오류나 B의 확정 실패로 집계하지 않는다. 전문은 원실험 뒤 확보한 추가 입력이며 원평가를 덮어쓰거나 절차 효과로 계산하지 않는다.

E2 P011의 추가 국소수정도 한 차례 직접 시도했다. 제공 판결만으로 법원의 consent와 정부의 신규 licence 정책 예외를 함께 확정할 수 없어 **추가 patch 0, 원문 유지/보류**로 끝냈다. 이미 지지된 추출 금지 정정은 유지했다. 단어 하나를 바꾸면 충분해 보여도 정부 정책의 적용범위를 새로 단정할 위험이 있어 자동 수정하지 않았다. 이는 해결된 사례로 세지 않는다.

후속 정책 조사에서도 당시 [영국 정부의 의회 답변](https://hansard.parliament.uk/commons/2025-01-30/debates/AE92DAFD-9CB2-4751-84D5-DCC3FA5742D6/BusinessOfTheHouse)은 환경영향평가 지침 일정만 확인했다. 2회 검색 호출·4개 공식 페이지 확인 범위에서 필요한 정책 경계를 확정하지 못했다. 자료 공백을 추정 문장으로 채우지 않고 보류를 유지한다.

## 바로 적용할 짧은 절차

1. 원문·원자료·질문·사건/발표/회수 시점을 고정한다. 전체 본문인지 발췌인지 표시한다.
2. 기존 체크리스트를 보지 않은 검토자가 원문에서 보호할 구간과 이유를 만든다. 그 후 다른 목록과 대조한다. 원문에 있던 의미, 자료에만 있는 추가 배경, 질문에 필수인 답을 나눈다.
3. 원문과 근거가 실제로 다른 문장/절에만 정확한 patch를 제안한다. 귀속·조건·반론·강도·시간을 보존하고, 관련된 다른 문장을 자동으로 같이 바꾸지 않는다.
4. 원문/O+P/O+P+Q를 비교해 P가 새로 깨뜨린 명제가 있는지 본다. 수정 위치·해시·원상복구를 검사한 다음, 별도 검토자가 전체 실제 후보를 다시 원문·자료 양방향으로 읽는다.
5. 새 손실이 확인되면 해당 patch를 롤백한다. 해석/필수성/자료 충돌이 해소되지 않으면 보류한다. 개별 patch가 안전해도 전체 기사에 핵심 기존 오류가 남으면 전체 승인하지 않는다. 분량 내 보존 불가이면 길이 증가 필요를 표시한다.

## 해결 상태와 남은 문제

- **해결한 국소 결함:** 재현된 경로 덮어쓰기·잘못된 ID 집계·겹친 anchor·관계판정 누락 허용. 시험한 조건과 코드 버전 범위에서만 해결이다.
- **부분 해결:** 조건·시간을 되살리는 최소수정, 근거 있는 비판/반응 유지, 관련성과 필수 의존성 구분, 원문에서 독립 누락 검사. 기사 일부에서 지지되지만 보편적 효과는 아니다.
- **미해결:** 보호할 의미 목록의 완전성, 원문에 남은 오류의 수정 필요성, 세부 조건의 중요도, 평가자의 필드 해석·보류 기준 안정성. E1의 필수성 이견과 K01의 전체 hold가 자동 승인으로 끝낼 수 없는 실제 사례다. 목록에 항목을 추가해 그 사례만 고치는 것은 노출 사례 회귀이며 일반해법 검증이 아니다.
- **자료·검증 의존:** 한국어 정상 후보의 당일 표결·법안 원문과 직접 반론, LK-99 당일 직접 답변/측정 원자료, 복합 정상기사 추가 대조, 실제 인간 검토가 부족하다. 숨긴 4건은 이제 노출되었으므로 이후 개선에는 새 holdout이 필요하다. 모델/seed/비용 통제 부족은 작은 실험으로 사라지지 않는다.
