# Exposed regression: source-linked unresolved-issue sidecar v1

This is a bounded development regression using FOUR ALREADY EXPOSED authored library scenarios, not a new holdout or a semantic-truth test. Existing state receipt bytes must remain unchanged. Add a separate optional display of supplied review assertions. There is no native writing and no automatic semantic adjudication.

Input JSON schema: `schema`="journal-v11.issue-sidecar-input.v1"; `input_id` string; `language` KO|EN; `actual_output` UTF-8 string; `output_sha256` lowercase hex; `receipt_address` object `{path:string, json_pointer:string, file_sha256:string, receipt_sha256:string}`; `evidence` array of `{id:string,text:string,sha256:string}`; `issues` array of issue objects. `receipt_sha256` is SHA-256 of canonical JSON (`json.dumps(receipt,ensure_ascii=False,sort_keys=True,separators=(',',':')).encode('utf-8')`). File hash binds the exact containing file. Pointer is `/actual_receipt`. It points to the existing verified state receipt; this module does not regenerate or rewrite it. Receipt's output_sha256 must match actual_output. No authentication beyond supplied bytes is claimed.

Each issue object has `id` (unique string), `kind` exactly `question_comparison` or `arithmetic`, `review_status` exactly `reported_unresolved`, `output_span` = `{start_byte:int,end_byte:int,text:string,sha256:string}`, and `evidence_span` = `{evidence_id:string,start_byte:int,end_byte:int,text:string,sha256:string}`. Spans are exact nonempty slices of the UTF-8 encoded corresponding output/evidence strings; end exclusive. Whole evidence text is allowed. Verify bounds, exact bytes and slice hash. Verify each evidence document hash too. No natural-language conclusion is accepted as an issue field. No field may silently change supplied review status into verified error or resolved truth.

The renderer lists issue ID, controlled kind, quoted output span, quoted evidence span, and a FIXED localized caveat: "Supplied review reports this issue unresolved; the sidecar does not independently verify the claim." / "제공된 검토는 이 문제를 미해결로 보고합니다. 이 보조표가 그 주장을 독립 검증하지는 않습니다." It must show all supplied issues without changing actual_output or receipt. With `issues=[]`, display "No unresolved issues were supplied; this does not establish that all issues are resolved." / "제공된 미해결 문제 목록은 비어 있습니다. 모든 문제가 해결됐다는 뜻은 아닙니다." Do not synthesize replacement text or infer that a patch was applied, that an error is proven, that external publication occurred, or that the article is verified.

A sidecar output should bind schema version, input hash, output hash, canonical receipt hash and all validated issue records, plus deterministic rendered text. Validation failure must refuse generation/acceptance, not silently drop issues or anchors. Re-verification must regenerate the complete object and compare exact fields/text; modified render prose must not pass just because hashes inside it remain unchanged. Function/API naming is implementation choice. No requirement to recalculate the upstream receipt's entire decision engine in this new module: validate address/file/object/output binding, and retain upstream receipt validation as the precondition.

Only this contract and examples are available to the implementer before code freeze. Examples use generic foo/bar, separate from four scenario cases. Inputs/keys are independently locked. After code freeze root may run the four inputs once. Paired reader display: status-only versus same status plus sidecar, identical source/output/receipt/evidence; four cases × two conditions × two readers = 16 AI judgments. Full common data may let readers recover issues without annotation; report annotation recoverability separately. No new writing or expansion after results.
