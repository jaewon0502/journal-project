# 실제 실행 조건 확정 — 판정 전

고정 확인 계약의 authored comparator를 보존한다. 주 비교는 NATIVE_FINAL(실제 native 자유 작성10개) 대 RECEIPT_FINAL(결정적 생성10개)이며, 두 조건은 같은 원문·patch·실제 산출물·구조화 영수증·근거를 받았다. AUTHOR_PROPOSAL(설계자가 만든 검토 단계 메모10개)은 별도 진단 대조로 함께 읽되 AI 작성 성과로 세지 않는다. 총30표시 packet, 원사례10변형이다. 하나의 가상 도서관 소재를 언어/상태 조건으로 바꾼 것이므로 서로 독립된10사건이 아니다.

자유 메모/코드 메모 모두 영어200단어·한국어900문자 상한이다. 최소길이로 억지 패딩하지 않는다. 실제길이를 보고한다. 표시 packet의 원문·최종본문·receipt·근거는 동일하고 annotation만 다르다. 코드조건은 근거 설명을 자동 판정하지 않으므로 구체 의미 문제의 전달 누락을 별도 보고한다. 전제는 임의로코딩한 정답을 모델출력으로 세지 않는다.

설계자의 예상답은 gold가 아니다. 기계적 mutation 여부·hash는 재생 가능한사실이고, 의미 충분성/미확인상태 질문은 단위와지칭을 확인해 원판정을 보존한다. 모델독해 비교는별도문맥의 AI내부검토일뿐 인간이해 측정이 아니다. 스타일단서로조건추정가능, 전체blinding보장않음.
