# Journal v11 — 적용 영수증과 상태 문장: v10 후속 회차

2026-10-01 23:12:33 UTC 계획 고정. 실제 입력별 freeze는 별도 manifest. 최종 완료 상한 2026-10-02 00:30 UTC, 신규 배치 00:15 중단. v10 파일/보고서/Library 항목은 checkpoint로 보존한다. 유료 API·추가 인증·외부 게시·원격 변경 없음.

## 인과 가설과 비교 범위
v10에서 제안 시점 메모가 후보 작성/최종 승인 이후에도 남았다. 구조화된 상태 원장과 자유문장 메모가 두 개의 상태 출처가 되어, 같은 묶음에서 다른 시점을 가리킬 수 있었다. 해법 후보는 상태 표현을 불변·내용주소형 적용 영수증에서 생성하는 단일 경로로 제한하는 것이다. 해시의 일치는 서명자 인증이나 의미 진실 인증을 뜻하지 않는다.

상태 문장은 no-op/applied/partial/rolledback/abstained를 구분한다. 원문→수정안→실제 산출물 바이트를 재생하여 영수증/최종 산출물 일치를 확인하고, 손상·오래된 자료·부분 저장 실패·경로 충돌이면 완료를 표시하지 않는다. 적용 내역과 외부 게시, 사실 진위, 질문 해결, 근거 범위를 분리한다.

개발 예시는 구현자가 작성한다. 별도 설계자가 확인용 KO/EN 10합성 사례와 기계적 오류 주입을 먼저 동결한다. 구현자는 확인 내용 열람 없이 버전동결. root가 고정 인터페이스에 adapter를 작성하되, 내용을 바꿔 맞추지 않으며 오류/미지원은 그대로 기록한다.

확인 기본 비교는 같은 원문·실제 최종 본문·patch 결과·근거 범위를 입력으로 두고 (A) fresh native 모델의 자유 작성 상태 메모, (B) 고정 코드가 생성한 영수증 메모를 만든다. B는 모델 출력이 아닌 결정적 코드 출력이다. A도 동일 사실·상태 정보를 받게 하여 고의로 불리한 자료 조건을 만들지 않는다. 둘 다 원본문을 다시 쓰지 않는다. 목표 길이는 짧은 상태 설명이며 영수증/근거 범위 정보는 두 조건 공통으로 제공한다. 조건 라벨을 가린 별도 독자2가 개별 명제를 읽어 판정한다. 언어 스타일에 따른 조건 추정은 완전히 막을 수 없다.

v10의 옛 메모와 새 메모 비교는 이미 노출된 회귀이다. 자유 작성보다 반드시 우수하다고 가정하지 않는다. 정상대조·의존/독립수정·원복/유보·부분적용을 구분하고, 완료를 잘못 주장하는지와 사실 이해·정보 손실을 따로 보고한다. 손상 영수증 기계적 차단은 AI 독해 정확도와 별도 집계한다.

만장일치 승인된 v10 사례5개를 독립 독자가 원문·근거에서 재검토한다. 최초 판단 저장 후 제기하는 추가 질문은 사후 진단으로 구분한다. 새 원문/미사용 실기사 성능으로 세지 않는다. 상태만 남기는 템플릿이 근거 설명·시간·발언·조건 정보를 버리는지도 확인한다. 미확인을 거짓으로 확정하지 않는다.

모델 override 없이 native 별도 문맥. 정확한 배포 버전/seed/비용/토큰 사용량은 미제공. AI 내부 검사이며 인간/교차 모델 독립 검증이 아니다. 코드시험·수집범위·상태 전달·의미 판정을 하나의 성공 점수로 합치지 않는다. 확인 결과를 본 뒤 고치면 동일 사례는 회귀가 되며 새 holdout으로 부르지 않는다. 이번 회차는 한정된 묶음과 원인 해석으로 마감하고 무기한 재수정하지 않는다.
