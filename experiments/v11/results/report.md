# Journal v11 — 최소편집의 실제 상태와 의미 보존을 분리한 후속 연구

**국소적으로 고친 부분은 있지만 세 문제의 일반 해법은 아직 없다.** 원문 밖을 다시 쓰지 않는 최소편집과 실제 적용 영수증은 구현·시험했다. 그러나 영수증만 남기면 구체적인 미해결 의미가 사라졌고, 원문을 한 글자도 삭제하지 않은 추가 설명도 원문의 뜻을 강화할 수 있었다. 평가자의 합의 역시 이 문제를 자동 해결하지 않았다.

v10은 이번 두 시간 연구의 앞부분 checkpoint다. 이 보고서는 v10을 덮어쓰지 않는 별도 v11 후속 결과이며, 원래 A–D 및 이전 74출력 실험의 재평가 점수로 합치지 않는다. 외부 Page·원격 저장소·운영 기사는 변경하지 않았다. 아래 적용·허용은 작업환경의 로컬 산출물을 뜻한다.

## 1. 세 갈래 연구와 이번 후속의 연결

|문제|앞선 v10 병렬 산출물|이번 v11에서 추가 확인|현재 결론|

v10에는 실제 native 작성9개, AI 의미 판정51개가 있었다. v11은 새 native 최종 메모10개와 정밀도 미세비교 작성4개, 메모 독해60판정과 정밀도8판정, 마지막 보조표 비교16판정을 추가했다. 따라서 v11의 실제 native 작성은14개, 이 세 묶음의 판정은84개다. 별도 원문 도전검토5건과 사후 정밀도 진단은 별도 질적 기록이다. 코드가 만든 영수증10개·미해결 보조표4개·합성 기대값·동일 입력 재실행을 모델 출력이나 새로운 사건으로 세지 않았다.

## 3. 실제 적용 상태를 하나의 기록에서 생성

v10에서는 제안 시점의 자유문장 메모가 최종 후보에 남아 “아직 적용 전”이라고 읽혔다. 새 영수증은 원문·제안 patch·감사·실제 최종 본문을 정확히 재생하여 상태를 만든다. no-op, 전체 적용, 부분 적용, 원복, 보류를 구분하고, 다른 본문이나 오래된 기록을 붙이면 완료를 표시하지 않는다. 외부 게시·전체 사실 검증·질문 해결 여부는 적용 상태에서 추론하지 않는다.

독립 설계자가 KO/EN10개 확인 변형과6개 손상 변형을 구현 동결 전에 잠갔다. 10개는 한 가상 도서관 상황을 언어·적용 상태로 바꾼 합성 자료다. 서로 독립인 실제 사건10개가 아니다. 최종 본문·적용ID·해시가 **10/10 잠금 기대값과 일치**했고, 손상 본문·오래된 영수증·부분 저장 오류6개는 **6/6 완료 표시 없이 거부**됐다. 정상 no-op2, 전체 적용3, 부분 적용2, 원복2, 보류1이었다.

예: 21%→24%를 ‘3%’라고 쓴 절과 회의 요일을 각각 수정 제안했으나 요일 patch는 거부된 사례에서, 실제 결과는 ‘3%포인트’만 적용되고 금요일은 남았다. 거부됐다는 사실이 금요일의 진실을 증명하지 않는다. 의존된 두 patch 중 하나가 거부되면 묶음을 원복한다. 적용 상태와 남은 의미 문제를 분리해 설명해야 한다.

영수증의 해시는 내용 일치를 확인하지만 감사자 신원을 인증하지 않는다. 파일 소유자가 임의로 바꾸는 것까지 방어하는 보안 저장소도 아니다. 원문·감사 입력 자체의 진실은 이 코드의 보증 범위 밖이다.

## 4. 상태 설명을 개선하면서 무엇을 잃었나

같은 원문·실제 본문·구조화 영수증·근거에 대해 실제 native 최종 메모10개와 코드 영수증10개를 만들었다. 독립 독자2명이 조건 이름을 가린 상태에서 읽었다. 설계자가 쓴 제안 단계 메모10개는 별도 단계 대조이며 모델 출력이 아니다. 총30개 표시물×2독자=60판정이다. KO900자/EN200단어의 같은 상한을 썼지만 실제 길이는 같지 않았다.

|평가 항목|native 최종 메모,20판정|코드 영수증,20판정|
|---|---|---|
|실제 적용 여부 명시|20|20|
|구체적 의미 상태 전달|명시18·암묵2|누락20|
|전체 사실 검증 한계|명시4·암묵8·누락8|명시20|
|외부 게시 한계|명시6·누락14|명시10·암묵10|
|새 unsupported claim으로 기록된 항목|0|0|

구체적 의미 상태 누락20판정은 미해결6사례×2독자=12판정과 범위 안 문제 없음/해결4사례×2독자=8판정이다. ‘20건 모두 사실 오류’가 아니다. 영수증은 금요일이 남았다는 점, 단위·요일 두 문제가 원복됐다는 점, 별개 합계8+5=14가 여전히 있다는 점을 구체적으로 말하지 않았다. native는 이를 전달했다. **영수증으로 의미 설명 전체를 대체하는 해법은 지지되지 않는다.**

주 질문6개의 A/B 답은 모두 같았지만 모든 조건에 구조화 영수증이 공통 제공됐다. 따라서 메모만 읽었을 때의 이해력이나 사람의 이해도를 입증하지 않는다. 평가자는 형식으로 조건을 추정할 수도 있다. 코드 영수증은 KO601–618자/EN118–124단어로 native KO213–307자/EN63–92단어보다 길었다. 시간·비용 우위를 측정하지 않았다.

## 5. 평가키도 원문처럼 감사해야 한다

‘이 기록이 기사 전체의 정확성을 입증하는가?’라는 질문에 두 독자는 모든 조건에서 no라고 답했다. 설계자는 ‘기사 전체가 실제로 참인지’에 대해 unknown을 기대값으로 넣었다. **입증하지 못한다는 no와 세계 사실을 모른다는 unknown은 양립한다.** 원키와 원판정을 유지했으며, 문자 그대로의 일치는 조건별0/20, 세 조건 합계0/60이지만 이를 독자의 사실 오류로 부르지 않았다. 다른5질문은 조건별20/20 키와 일치했다.

메모의 명시/암묵/누락 판정은180개 A/B 명제 짝 중3개에서 달랐다. 주 질문 답의 일치가 설명의 충분성까지 같은 것을 뜻하지 않는다. 동의율·근거 지지·누락·기계 검증을 단일 성공 점수로 합치지 않았다.

## 6. 질문의 단어를 고쳐도 남은 의미 강화

원 기후 기사는 ‘one-hundredth’라고 보고했지만, v10 목표 질문은 ‘exactly’를 추가했다. 새 원자료의0.01 미만이라는 수치는 지지되지만, 원문이 반올림 전 정확히0.01을 주장했고 반박됐다는 결론은 별도 입증되지 않았다. 표시된16.96과16.95가 있다고 해서 원래 정밀도·반올림 방식·실제 인터뷰 발언을 확정할 수 없다.

**v10 해석 정정:** ‘정확히0.01이라는 원문 오류를 고쳤다’는 취지로 읽힐 부분은 축소한다. 지지되는 것은 원자료 설명의 추가와 원래 귀속·불확실성 보존이다. 원문이 정확한 반올림 전 수치를 잘못 주장했다는 입증은 없다. v10 원출력·원평가·Library 파일은 보존하고 이 정정을 별도로 남긴다.

같은 노출 기사에서 목표 질문의 ‘an exactly one-hundredth’를 ‘a one-hundredth’로 바꿨다. 그 밖의 의미 입력은 동일했고, 조건별 새 native 출력2개를 만들었다. 조건과 질문을 숨긴 두 독자가4출력을 검토했다.

|작은 비교|정밀도 강화 yes|강화 no/모호|수치 충돌을 주장한 출력|
|---|---|---|---|
|exactly가 있는 질문,2출력|1|모호1|1|
|exactly를 뺀 질문,2출력|1|no1|1|

위 분류는 후보 본문과 reader_note를 함께 본 판정이다. 강화 질문의 yes1건은 본문 자체보다 메모의 정밀도 해석에서 나왔다. 두 독자는 위 핵심 세 범주에서 각각 같은 판단을 내렸지만, 별도 unsupported-inference 존재 여부는4출력 중2개에서 달랐다. 원자료가 원문 정밀도를 반박한다는 근거는8판정 모두 부족하다고 봤다. 두 조건 모두 귀속·불확실성/동률·비판·앞선 날짜 문장은 보존했다. 따라서 **원문을 삭제하지 않는 최소편집도 새 연결문이 원뜻을 강화하는 실패를 막지는 못했다.** 단어 하나 삭제만으로 해결됐다는 결과도 아니다. 조건별2번, seed·정확한 모델 버전 미통제라 인과효과 크기나 일반화는 추정하지 않는다.

재현 가능한 실패 형태: 원문 ‘0.01 차이라고 전했다’ → 원문은 그대로 둠 → 추가문 ‘정확히0.01이 아니라0.01 미만이다’. 새 수치는 근거가 있어도, 원문에 없던 ‘정확히’와 반박 관계가 추가된다. 합당한 대안은 원자료가 말하는 수치를 따로 설명하고 두 표현이 실제 모순인지 판단을 유보하는 것이다. 이는 절차 후보이며 일반적인 방지 효과는 아직 검증하지 않았다.

## 7. 바로 쓸 절차와 중단 기준

1. 원문 범위·날짜·출처·해시와 질문을 고정하고, **질문에 원문에 없던 단정·정밀도·인과가 들어갔는지** 먼저 확인한다.
2. 원문에서 주체·발언 강도·조건·부정·반론 대상·시간/비교 범위를 짧은 위치별 보호표로 만든다. 별도 독자가 표를 안 보고 확보 원문을 다시 읽는다.
3. 오류 근거가 충분한 문장/절만 patch한다. 나머지는 그대로 두고 의존한 수정은 묶는다. 발언 귀속과 그 발언 내용의 진실을 분리한다.
4. 원문→후보 보존 검사와 후보→근거 지지 검사를 모두 한다. **추가문이 보존된 원문의 뜻을 새로 제한·강화·반박하는지도** 검사한다.
5. 실제 최종 본문에서 적용 영수증을 생성한다. 별도 의미 설명에는 해결한 질문·그대로 남은 문제·미확인을 구체적으로 쓴다. 원문/최종 본문 구간과 근거 위치가 연결된 미해결 보조표는 이 설명을 제한하는 후보이며, 목록에 없는 문제를 자동 발견해 주지는 않는다. 영수증만으로 그 설명을 대체하지 않는다.
6. 독립 검사에서 판정이 갈리면 같은 명제를 같은 자료 범위에서 답했는지 먼저 확인한다. 근거로 해소되지 않으면 해당 수정 또는 의존 묶음을 보류한다.

**중단:** 삭제/반박할 원문을 부정할 근거 부족, 중요한 조건이나 반론 확인 실패, 새 의미 강화, 본문–상태 불일치, 손상 입력, 길이 때문에 보호 의미를 유지할 수 없음. 길이가 부족하면 ‘현재 길이로 보존 불가·길이 증가 필요’를 표시한다. 이번에는 강제 압축 성능을 시험하지 않았으므로 이 규칙의 효과까지 측정한 것으로 보고하지 않는다.

## 8. 코드 수정·재현과 남은 한계

최초 영수증은 큰 감사 입력을 받아2MiB를 넘는 영수증을 만들지만 읽기/표시에서는 거부하는 경계 불일치가 있었다. 별도 v1.1은 동일 크기 제한을 생성·검증·표시·저장에 적용했다. 2MiB 바로 아래·정확히 경계는 성공하고1바이트 초과는 생성 전에 거부됐다. 원래 실패와 동결 버전은 남겨 두었다.

깊게 중첩된 JSON은 크기가 작아도 RecursionError를 밖으로 내보냈다. v1.2의 중첩 제한도 UTF-16/32 자료에서는 우회됐다. 깊이65의 정상 결박 감사가 제한을 넘어 허용됐고, 깊이10000에서는 예외가 밖으로 나왔다. 의미상 거짓 완료 주장 사례로 관측된 것은 아니지만 명시한 입력 제한과 실패 응답을 지키지 못한 결함이다.

최종 v1.3은 JSON을 UTF-8과 최대64중첩·2MiB로 명시적으로 제한한다. UTF-16/32 자동 인식은 지원에서 제외하는 호환성 축소다. 개발21시험과 독립20관련 시험을 통과했고, 독립 검사에서8인코딩 변형의 우회가 재현되지 않았다. 독립 검사는 앞서 실행한 큰30000항목 시험을 중복 실행하지 않았다. 이전 실패 코드는 보존했다.

잠금10사례의 영수증 바이트·표시문은 네 버전에서 동일했다. 이는 노출 사례의 버전변경 회귀 검사다. 별도 이식성 실행은 원 의존 경로 한 줄만 실행 메모리에서 바꿨으며 원본 코드는 그대로 남겼다. 원 로더와10합성 변형의 결과가 같고, 원 경로 접근을 금지한 다른 위치에서도 실행됐다. 아직 재현된 실패가 없다는 것이 모든 입력에 대한 보증은 아니다. 입력 신뢰·운영 인증·모델 의미 정확성은 이 코드시험으로 해결되지 않는다.

native는 별도 문맥으로 실행했으나 같은 런타임 계열이다. 정확한 배포 버전·seed·호출 비용·토큰은 제공되지 않았다. 비용 절감, 인간 신뢰/이해도, 다른 모델 계열 재현성을 주장하지 않는다. 합성 raw·코드·집계는 재실행 자료에 포함하고 실기사 전문은 포함하지 않는다. 자연어 출력을 같은 형태로 다시 생성하는 것은 보장하지 않는다.

## 10. 마지막 제한된 개선: 근거에 연결한 미해결 보조표

영수증 단독의 정보 누락을 본 뒤, 실제 최종 본문 구간과 근거 구간을 정확한 UTF-8 위치·해시로 연결하는 별도 보조표를 구현했다. 자유롭게 새 결론을 쓰는 대신 정해진 종류·구간·‘제공된 검토가 미해결로 보고함’이라는 한정만 표시한다. 기존 영수증을 전체 재생 검증한 다음 보조표를 붙인다. 빈 목록은 ‘모든 문제가 해결됐다는 뜻은 아니다’라고 명시한다. 길이 한도를 넘으면 항목을 몰래 빼지 않고 전체 생성을 거부한다.

입력4개와 질문은23:50 UTC에 고정했고 구현은23:57 UTC에 동결했다. 부분 적용·의존 원복·상속된 합계 오류·정상 no-op이라는 **이미 노출된 합성4사례**다. 알려진 실패에 맞춰 준비한 회귀 수정이며 새 holdout이나 일반적인 누락탐지 성능이 아니다. 총4개 미해결 항목이3사례에 있고 정상1사례의 목록은 비어 있다.

같은 본문·근거·기존 영수증·공급된 문제 목록을 두 조건에 공통 제공하고 상태문만/상태문+보조표8개 표시물을 새 독자2명이 평가했다. 총16판정이다. 작성자는 없고 추가 보조표는 코드 출력이다.

나머지 정상사례2판정의 문제 파악은 해당 없음이다. 네 질문의 A/B 답 불일치는 없었다. 상태문만 받은 독자도 공통 입력을 보면 문제를 찾을 수 있었으므로 사람의 이해도나 전체 입력 처리 성능이 개선됐다는 뜻이 아니다. 개선된 것은 **선정된 미해결 항목이 표시문에도 드러나는 국소 전달**이다.

예를 들어 부분 적용 결과의 ‘금요일’과 가상 일정의 토요일 구간을 함께 표시하되, 수정 거부가 금요일의 참을 입증하지 않는다는 경계를 유지했다. 합계8+5=14도 실제 최종 본문 위치와 주어진 수치 자료를 연결했다. 원문·수정문·영수증은 바꾸지 않았다. 개발8시험과 별도 코드검사6개가 통과했고, 길이 경계400/1600은 허용·401/1601은 거부한 기록이 남았다. 환경 재연결 시점에는 독립 감사자의 설명 보고서가 없었다. 최종 편집자가 그 감사자의 코드·결과JSON·실행 로그에서 설명 문서를 작성했으며, 이를 새로운 독립 검토로 부르지 않는다.

**여전히 못 푼 부분:** 목록에 넣지 않은 중요한 조건·반론·시간 관계는 이 장치가 찾아내지 못한다. 잘못 선정된 문제도 구간 자체가 존재하면 별도 의미 검토가 필요하다. 따라서 보호목록을 실패마다 늘리는 것을 일반 해법 검증으로 볼 수 없다. 영수증은 실행 상태, 보조표는 공급된 미해결 주장과 위치, 독립 원문 검토는 목록 밖 의미를 각각 맡는 방향까지만 지지된다.

## 12. 최종 수치·공개 범위 점검

보조표16판정은 문제 있는3사례×2조건×2독자=12판정과 정상1사례×2조건×2독자=4판정이다. `0/6→6/6`은 문제 있는3사례의 각 조건6판정끼리 비교한 값이다. ‘개선조건6판정+나머지10대조’로 볼 때 나머지10은 문제 있는 사례의 상태문 대조6과 정상사례의 양조건4다. 미해결 항목은 부분적용1개·의존원복2개·기존합계1개로4개이며, 항목 수와 사례 수를 구별한다.

본 영수증 확인10합성 변형은 구현 전 별도 설계자가 동결했다. 보조표4사례는 그 결과를 이미 본 뒤 고른 노출 회귀이며 개발용 실패사례다. 알려진 문제를 손으로 선정했다. 같은 런타임 계열의 별도 문맥 AI 내부평가이고, 새로운 문제 발견·새 사건 전이·사람의 이해도·다른 모델 계열 재현성을 뜻하지 않는다.

기계 검사는 최초 영수증 개발9시험·독립6시험 중5통과와1크기결함, 최종 v1.3 개발21시험·독립20관련 시험 통과로 구분한다. 중간 버전의 반복 시험을 합쳐 고유 총시험 수를 만들지 않는다. 별도 잠금10변형의 출력 일치와 손상6변형 거부도 독자 판정과 다르다. 오래된 본문/해시, 후보와 최종본문 교체, 잘린 저장물, 심볼릭/하드 링크·FIFO·기존 경로 충돌을 거부한 기록이 있다. 잘린 파일을 몰래 복구하거나 기존 경로를 덮어쓰지 않았다. 전체 장애 타이밍이나 파일 소유자의 악의까지 증명한 것은 아니다. 보조표 개발8·독립6시험은 별도 모듈이다.

v10의9작성·51판정과 v11의14작성·84판정은 서로 다른 원응답 파일 집합이다. 그러나 일부 실제 기사와 합성 기저 사례를 재사용했으므로23개 독립 사건이나135개 독립 관측으로 합산하지 않는다. 앞선 실험의 기존 원출력을 새 모델 출력으로 중복 계산하지 않았다.

공개 ZIP은 허용한 경로를 명시적으로 골라 만들었다. 실기사 전문·후보 전체·긴 원문 인용을 가진 자연자료 raw와 대화/위임 메모·Library 응답·환경 내부 메모는 제외했다. 포함한 원판정은 자체 합성 자료와 요청된 짧은 판정 근거다. 원문 전체와의 긴 연속구간 검사 및 파일별 내용 분류를 해시 검증과 별도로 수행했다. 해시가 맞는다는 이유만으로 공개 안전성을 판단하지 않았다. 원자료 링크·짧은 보호 구간·위치·해시·자체 생성 추가 구절·실험 프로토콜은 재현과 검토 목적으로 남겼다.
