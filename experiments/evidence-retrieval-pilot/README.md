# 공식 통계표에서 근거 행 찾기

기사 속 날짜와 단위를 표에 다시 대조할 때, 검색기가 편집자에게 맞는 행을 몇 번째로 보여 주는지 확인하는 소규모 시험이다. 한 질의에는 공식 자료 하나만 제공한다. 서로 다른 연도의 금액이 같거나 기사에 적힌 금액이 다른 연도와 일치해도, 질의가 가리키는 연도의 행을 정답으로 친다.

## 자료와 채점

| 원자료 | 발췌 범위 | 확인할 내용 |
|---|---|---|
| [한국은행 기준금리 추이](https://www.bok.or.kr/portal/singl/baseRate/list.do?dataSeCd=01&menuNo=200643) | 2022년 1월부터 2024년 11월까지 변경일자 행과 표의 주석 | 날짜별 금리, 금리 지표의 전환 시점 |
| [최저임금위원회 연도별 최저임금 결정현황](https://www.minimumwage.go.kr/minWage/policy/decisionMain.do) | 2020~2025년 적용연도 행과 표의 단위·머리글 | 연도별 임금과 인상률, 월 환산 시간 |

2026년 11월 23일 원문 표를 확인했다. [동결 자료](holdout.json)에 출처, 발췌 행, 질의, 정답 위치와 값을 보관했다. HTML 표의 한 행을 한 줄로 옮겨 열 사이를 탭으로 나누고, 셀 안에서 줄이 바뀌는 날짜는 공백으로 이어 썼다. 원문의 두 자리 연도와 선행 0, 쉼표를 유지했다. 줄 번호는 이 발췌본에서 매긴다.

- **첫 후보 적중**은 답이 있는 8개 질의 중 맨 위에 정답 행이 나온 건수다.
- **상위 3개 적중**은 같은 8개 중 세 번째 이내에 정답 행이 나온 건수다. 날짜가 다른 행에 같은 수치가 있거나, 정답 바로 옆 행이 나와도 적중으로 세지 않는다. 헤더 자체가 답인 질의는 1개다.
- **근거가 없는 질의의 후보 노출**은 두 표에서 알 수 없는 투표 내용과 임금 미달 인원을 물은 2개 질의 중 하나라도 후보가 나온 건수다. 후보가 나왔다는 사실만으로 편집자가 오판했다고 보지 않는다.

자료를 구성한 사람이 코드 실행 전에 위의 질의와 정답을 고정했다. 동결한 파일의 SHA-256은 `14be8517e99104ff7a4d3b7ec4b1344ed3ddfeaa75961c92015898f97f27723a`다. 채점 도구는 해시와 원문 위치·후보 본문이 일치하는지 먼저 검사한다.

## 동결 후 결과

| 지표 | 기존 | 변경 후 |
|---|---:|---:|
| 첫 후보에서 정답 행 확인 | 4/8 (50%) | 5/8 (62.5%) |
| 상위 세 후보에서 정답 행 확인 | 5/8 (62.5%) | 6/8 (75%) |
| 중심행이 모두 빗나간 질의 중 기본 화면의 주변 문맥에 정답 행 표시 | 0/3 | 0/2 |
| 자료에 답이 없는 질의에 후보 표시 | 2/2 | 2/2 |

2025년 최저임금 시간급(w1)의 정답은 3위에서 1위로 올랐다. 2020년 최저임금 인상률(w3)은 상위 세 개 밖에서 3위로 들어왔다. 2022년 4월 기준금리(b3)와 2022년 최저임금 일급(w2)은 두 버전 모두 상위 세 후보에서 근거 행을 찾지 못했다. 특히 w2는 질문에 적은 잘못된 일급 76,960원이 실제로 나온 **2023년** 행의 순위가 3위에서 1위로 올라갔다. 연도까지 대조해야 발견할 수 있는 오류다. [문항별 기존 결과](baseline-results.json) · [문항별 변경 후 결과](candidate-results.json)

[보조 지표](context-rule.json)는 변경 후 검색 결과를 보기 전에 따로 동결했다. 첫 세 후보가 모두 빗나간 경우에만, 검색 직후 카드 안에 정답 줄의 **번호와 원문 전체**가 함께 보이는지 확인했다. 주변 문맥을 펼치려면 한 번 더 클릭해야 하므로 기본 화면 노출로 집계하지 않았다. 기존과 변경 후 모두 별도 클릭 없이 추가로 확인된 줄은 0개였다. [Chrome 화면 확인 결과](context-results.json)

## 후보에 붙는 연·월 경고

두 번째 시험에는 [기상청 2024 지진연보 발간 보도자료](https://www.weather.go.kr/kma/flexer/html/press/2025/02/19/ATC202502191322352_93fe8588-81df-4b9d-a192-c2e98ae5c9bd.hwp.files/Sections1.html)의 인쇄 13쪽 표 4를 썼다. 실제 배포일은 2025년 2월 20일이다. 경주·포항·울산 지진 행에서 발생일시부터 위치까지 떼어내 날짜가 먼저 나오도록 했고, 앞에 순위와 규모를 그대로 둔 경주 행도 따로 확인했다. [질의·채점 기준·원본 PDF 주소](period-holdout.json)

구현을 열어 보기 전에 질의와 채점할 행을 정했다. 발표일만 바로잡은 최종 자료의 SHA-256은 `361e2ace39b0f015adf80929efc37e5c678f67727364a9ec9eb628f83695703b`다. 대상은 질문 8개에 대한 9개 행이다. 비교 질문은 양쪽 연도의 행을 각각 확인했다. 경고가 필요할 때는 후보 카드에서 요청한 기간과 실제 행의 기간을 정확히 읽을 수 있어야 한다. 검색 결과에 나오지 않은 행은 따로 보고한다.

지정한 9개 대상이 모두 세 후보 안에 나왔다. 첫 구현은 연도와 월이 다른 4개 행 모두에서 경고를 빠뜨렸다. 기상청 표의 날짜가 `2016-09-12 20:32:54`처럼 일과 시각까지 포함된 것이 원인이었다. 그 형식을 고친 뒤 **같은 질의·같은 행**으로 다시 확인했다.

| 후보와 질문의 관계 | 첫 구현 | 수정 후 재시험 |
|---|---:|---:|
| 연도가 달라서 필요한 경고 표시 | 0/2 | 2/2 |
| 같은 해에 월이 달라서 필요한 경고 표시 | 0/2 | 2/2 |
| 연·월이 일치하는데도 경고 | 0/2 | 0/2 |
| 두 해를 비교하는데도 경고 | 0/2 | 0/2 |
| 상대 연도만 주어졌는데도 경고 | 0/1 | 0/1 |

Chrome에서 각 후보의 순서와 원문이 그대로인지 함께 확인했다. 원표의 순위·규모가 날짜보다 앞서는 행은 별도 탐색 1건에서 두 버전 모두 경고가 없었다. [첫 구현의 Chrome 기록](period-results.json) · [같은 표본 재시험 기록](period-retest.json)

### 최저임금표의 적용연도 재시험

최저임금 표에는 날짜가 `'23.01.01 ~'23.12.31`처럼 두 자리 연도의 범위로 적혀 있다. 기상청 날짜 형식만 고친 시점에는 2022년 일급을 물은 w2의 첫 후보에 2023년 행이 떠도 경고가 없었다. 같은 문항으로 다시 검사한 결과, 범위 처리 수정 후에는 질문의 2022년과 해당 행의 원래 기간 표기가 함께 보였다(0/1→1/1). w1·w3의 연도가 맞는 정답 행에는 경고가 붙지 않았다(오경보 0/2). w3에서 금액이 같고 연도가 다른 2024년 행에도 경고가 떴다.

w2의 2022년 정답 행은 여전히 상위 세 후보 밖에 있다. Chrome에서 경고가 나온 첫 후보의 **주변 원문 확인**을 한 번 펼치자 바로 다음 7문단에 2022년 적용 행이 보였다. 그 행을 선택해 발췌 버튼을 누른 뒤 입력란의 값이 원자료와 탭·쉼표까지 같음을 확인했다. 이 문항에서만 확인한 수동 접근 1/1이며 자동 상위 세 후보의 적중에는 더하지 않는다. 이번 시간 범위 수정 후에도 기상청 표의 문항별 후보 순서와 경고 내용은 직전 재시험과 같았다. [최저임금표 수정 전후 Chrome 기록과 기상청 회귀 결과](wage-period-retest.json)

## 재현

프로젝트 최상위에서 실행한다. 첫 명령은 현재 파일을, 둘째 명령은 보관한 기존 검색기를 평가한다.

```sh
node experiments/evidence-retrieval-pilot/score.cjs docs/reader/evidence-finder.js
node experiments/evidence-retrieval-pilot/score.cjs experiments/evidence-retrieval-pilot/baseline-finder.cjs
```

[기존 검색 결과](baseline-results.json)는 이번 변경 직전 작업 사본에서 직접 얻었다. 그 파일의 SHA-256은 `f5bf97dfc93c866bdc6a0660923d9dc99055575b475aa785f4c3677ffb7bdf91`다. 검색기의 공개 커밋 `2c09396d7548c8521e60e0a3c96a59b5ea313429`도 이 10개에서 같은 순위와 행을 반환했다.

Chrome과 Playwright를 사용할 수 있는 환경에서는 다음 명령으로 화면의 보조 지표를 재현한다. 기본 단위 테스트에는 별도 브라우저가 필요하지 않다.

```sh
node experiments/evidence-retrieval-pilot/context-score.cjs docs/reader
node experiments/evidence-retrieval-pilot/period-check.cjs docs/reader
node experiments/evidence-retrieval-pilot/period-check.cjs docs/reader --wage
```

초기 기간 모듈로 다시 확인하려면 임시 폴더에서 아래 명령을 실행한다. 원래 작업 파일에는 영향을 주지 않는다.

```sh
reader_copy=$(mktemp -d)
cp docs/reader/*.html docs/reader/*.js docs/reader/*.css "$reader_copy/"
cp experiments/evidence-retrieval-pilot/initial-period.cjs "$reader_copy/evidence-period.js"
node experiments/evidence-retrieval-pilot/period-check.cjs "$reader_copy"
```

주변 문맥 보조 지표의 기존 화면은 위 커밋의 `factcheck-ui.js`와 이번 변경 직전의 검색기를 함께 열어 확인했다. JSON에는 사용한 각 파일의 SHA-256과 Chrome 버전이 들어 있다. 화면 채점기는 현재 후보 카드의 번호, 인용문, 번호가 달린 주변 문단 목록을 읽는다.

표는 두 개뿐이고 연도·금액을 의도적으로 혼동하기 쉬운 질의를 넣었다. 전체 문서에서의 탐색, 정치적 편향, 기사 전체의 사실성, 편집자의 시간·판정은 이 시험에서 측정하지 않았다. 결과 공개 후 같은 자료로 조정한 순위는 같은 표본에서의 재시험으로 기록한다.
