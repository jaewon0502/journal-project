# v14 후속: 수정 관계 분리·평가표·통제시험

2026-10-03에 새로 구현하고 실행한 후속 작업이다. **v14 원실행을 복구하거나 다시 채점한 결과가 아니다.** 제공된 HTML의 과거 수치(전체기사 1건, 제안 18개, 적용 6·보류 12, 잠정 보호항목 31/31)는 보고된 값으로 유지한다. v14의 K01 입력·평가 원본·실행 코드는 확보하지 못했다. 이전 PR #4의 법원 원자료·한국은행 실험과도 별개다.

## 실제로 바꾼 것

| 남은 문제 | 이번에 수행한 작업 | 확인한 범위 |
|---|---|---|
| 관련된 수정이 필수 의존성처럼 처리됨 | `related_context`와 `required_dependencies`를 분리한 새 게이트 | 단순 관련성은 보류를 전파하지 않는다. 필수 의존성의 이견·불확실성은 보류한다. |
| 필수 정정과 선택 설명이 한 수정에 섞임 | `necessary_correction` / `optional_enrichment` 분리, 원자적 수정 심사 | 선택 보충은 자동 채택하지 않는다. 문구를 실제로 분리했는지는 AI가 판단하며 코드만으로 보장하지 않는다. |
| 최초 평가와 최종 전달문이 달라질 수 있음 | 입력·두 평가 원파일·선택 ID·최종 후보 해시를 묶는 별도 최종감사 | 감사 전에는 `awaiting_audit`, 공개 허용 false. 다른 문구·오래된 감사는 거부한다. |
| 사람 양식에 문맥 안전성 없음 | [보충 양식](review.html)에 문맥 안전성, 대상 해시, 검토 시각 자기기록, AI 노출 순서 기록 추가 | 브라우저 기능 검사 수행. 실제 사람 응답·블라인딩·인간 일치 입증은 아님. |
| 미확인 자료 표 중복 | 원본 13행을 5주제로 통합 | 원문 위치·필요한 자료·당시 시점의 한계를 보존했다. 해당 사실을 새로 확인한 것은 아님. |
| 정상 글을 불필요하게 고치는지 미측정 | 가상 원자료 3건으로 만든 한국어 글 6개를 두 AI가 각각 평가 | 원자료 충실 구성 3개는 두 AI 모두 유지, 오류 주입 구성 3개는 모두 수정 제안. 실제 뉴스의 오탐률은 아님. |

[새 코드](code/gate.py)와 [정확한 데이터 계약](protocol/RELATION-CONTRACT.md)은 기존 v13 코드와 분리했다. 기존 v13의 `dependencies` 정의가 버그였다고 소급 주장하지 않는다. P2/P5 문제의 관계 구조는 **가상 문구로 만든 회귀시험**으로 검사했다. 원래 P5가 단독 적용돼도 안전하다는 의미 판단까지 복구한 것은 아니다.

개발 중 별도 검토에서, 단순 관련 문맥 목록의 차이만으로 다시 보류하던 과도한 규칙을 수정했다. 두 평가자가 필수 의존성과 문맥 안전성에 동의하고 분석 완료를 표시하면 비필수 주석 차이는 최종감사에 전달한다. 필수 여부 자체가 다르거나 분석이 불확실하면 여전히 보류한다.

## 자료 재확보와 P3 최소 정정

[확보 기록](data/provenance.json)에 기사 HTML, S1 193쪽 PDF, S2 40쪽 PDF, S3 후속 설명의 공식 URL·취득 시각·해시를 기록했다. 기사 본문 35문단을 다시 추출했고 S1의 표지와 물리 50쪽(인쇄 40쪽)을 시각 대조했다. 원자료 전문은 공개 Git에 넣지 않았다.

P3의 핵심은 가구의 자녀 수와 첫째·둘째·셋째 이후의 순서별 공제액을 구분하는 것이다. [새 후보 A](data/p3-alternatives.json)는 그 구분만 수정한다. 기존 보고서의 후보 B는 같은 정정에 연령·대상·손자녀·적용시점 설명을 더한다. [좁은 AI 비교](data/p3-narrow-review.json)는 둘 다 해당 금액 혼동을 해소하며 B의 추가 설명은 근거 있는 보충으로 판단했다. 기존 문맥을 읽은 AI의 비교이고 블라인드 성능시험이 아니다.

S1 표지의 위원회 변경 가능성·최종 확인 경고는 남아 있다. 최종 발표본 동일성, 현재 세법, 전체 233쪽 의미 감사를 확인한 것으로 표현하지 않는다. 재다운로드는 과거 K01 JSON과 원평가 출력의 복구를 대신하지 못한다. 보충 양식의 검토 대상은 **기존 P3 후보 B**이며, 입력을 후보 A의 사람 평가로 재사용하면 안 된다.

## 정상 구성과 오류 구성의 실제 AI 시험

[입력](data/control-input.json)은 새로 작성한 **가상 원자료와 완성된 짧은 한국어 글**이다. 도서관 예약 조건, 온도 관측의 인과 해석, 박물관 입장 집계 단위라는 3개 자료군에서 원자료 충실본과 한 곳을 바꾼 오류본을 각각 만들었다. 자연 기사 6건이 아니며 짝을 이룬 변형본이다.

[구성 레이블](data/control-construction.json)은 입력 제공 전에 저장했다. 운영자가 작성한 구성 의도이며 독립 인간 정답이 아니다. 두 평가자에게는 입력만 제공하고 레이블·동료 판정을 제공하지 않았다. 새 에이전트 수 제한으로 기존 보고서 검토/코드 구현 문맥을 재사용했고, 이를 [프로토콜](data/control-protocol.json)에 수정 기록과 함께 공개했다. 같은 모델 계열이며 대화 이력 없는 새 문맥, 기술적 격리, 서로 다른 모델의 독립성이 아니다.

| 평가 기록 | 충실 구성 3개 | 오류 주입 구성 3개 | 그 밖의 문구 수정 |
|---|---|---|---|
| [r1](data/control-review-r1.json) | 유지 3, 수정·보류 0 | 수정 제안 3, 유지·보류 0 | 주입 구간 밖 변경 0 |
| [r2](data/control-review-r2.json) | 유지 3, 수정·보류 0 | 수정 제안 3, 유지·보류 0 | 주입 구간 밖 변경 0 |

[재집계](data/control-results.json)는 판정·정확한 근거 구절·수정 범위와 후보 해시를 확인한다. 두 평가의 관측을 합쳐 독립 12사건이나 정확도 100%로 만들지 않는다. 수정문이 충실본과 문자열까지 같지 않은 경우도 기록한다. 이 코드 검사는 수정문의 의미가 옳음을 판정하지 않는다.

## 실제 평가 기록과 새 게이트의 연결

이미 평가한 가상 도서관 사례 1건을 재사용해, 저장된 정정 제안을 두 AI가 새 계약의 4축·원자성·필수 의존성으로 검토했다. 별도 최종감사자는 동료 판정 없이 정확한 최종 후보·원문·원자료를 대조한다. [진행 조건](data/integration-protocol.json), [초기 검토 r1](data/integration-review-r1.json), [초기 검토 r2](data/integration-review-r2.json), [감사 전 결과](data/integration-provisional.json)를 보존한다.

[최종감사](data/integration-audit.json)는 해당 후보를 승인했고, [최종 게이트 결과](data/integration-final.json)는 `awaiting_audit`에서 `approved`로 전환됐다. 감사 전에는 공개 허용이 false였으며 정확한 후보에 대한 별도 감사 후 true가 됐다.

이는 적응적 연결 시연이다. 새로운 독립 사건이나 미사용 평가군 성공으로 세지 않는다. 각 역할은 이전 작업 문맥을 재사용했으며, ID가 다르다는 사실은 신원·독립성을 증명하지 않는다. 코드는 인터넷에 게시하지 않고 해당 후보에 대한 절차상 허용 상태만 반환한다.

## 다시 실행하기

Python 3.11 이상, 이 패키지 자체는 표준 라이브러리만 필요하다. 저장소 전체 검사는 루트의 의존성 안내를 따른다.

```sh
python -m unittest discover -s experiments/v14-followup/code -p 'test_*.py' -v
python -m unittest discover -s experiments/v14-followup/tools -p 'test_*.py' -v
python experiments/v14-followup/tools/replay_controls.py --check-saved
python experiments/v14-followup/tools/replay_integration.py
python tools/run_checks.py
```

단위시험은 게이트 25개와 재집계 10개다. 재집계기는 중복 JSON 키, 겹치는 비고유 문구, 바뀐 입력·인용을 거부하고 실패를 비정상 종료 코드로 전달한다. 읽은 원바이트를 해석과 해시에 함께 사용한다. 공개 CI는 **저장 결과의 재계산**이며 새 AI를 호출하지 않는다.

[브라우저 검사 기록](tools/review-form-browser-evidence.json)은 실제 Chromium `file://`에서 7개 묶음의 합성 UI 검사를 실행한 결과다. 빈 기본값, 저장·새로고침·명시적 복원·JSON 내보내기, 대상·해시·형식이 잘못된 27종 기록의 거부, AI 노출 전후 편집 기록, 저장 불가 시 안내를 확인했다. 외부 HTTP 요청·JavaScript 오류는 0이었다. 다른 브라우저·미리보기의 저장 지원까지 보장하지 않는다.

Playwright와 Chromium을 가진 환경에서는 다음을 실행할 수 있다. 필요하면 `NODE_PATH`와 `BROWSER_EXECUTABLE`로 설치 위치를 지정한다. 브라우저 시험은 보관된 UI 증거 파일을 갱신하므로 실행 후 파일 해시 목록도 갱신해야 한다. Python CI가 브라우저 시험을 새로 수행한 것으로 표현하지 않는다.

```sh
python experiments/v14-followup/tools/build_review.py
node experiments/v14-followup/tools/test_review_form.mjs
```

## 여전히 남은 범위

- 원본 v14의 K01 JSON·원평가·실행 코드가 없어 과거 6개 적용·12개 보류의 직접 재현은 미완료다.
- 새 게이트와 UI는 구현·시험했지만 실제 여러 매체의 자연 기사에 대한 과잉수정·보류율은 아직 측정하지 못했다.
- 목록 밖 의미의 완전한 회수, 사람의 중요도 판단과의 일치, 다른 모델 계열에서의 재현성은 미입증이다.
- 추가 원자료 다섯 주제의 사실확인은 통합 목록으로 남았다. 새 후보 A는 미확인 범위 전체의 해결이 아니다.

원래 다운로드 HTML·v13 기록·PR #4 데이터는 변경하지 않았다. `SHA256SUMS`는 공개 파일의 현재 바이트 무결성 목록이며, 내용의 진실성이나 연구 독립성을 공증하지 않는다.
