# Runtime and fixed output contract

All native roles use fresh separate contexts with no model or effort override. They use the current inherited runtime. Exact deployment, seed, token usage and monetary cost are unavailable. Role separation does not make them different model families or human evaluators. No API/CLI model execution, payment, authentication or permissions changes.

The schema is a specification, not an example answer or expected content. Arrays may be empty. No known-defect inventory, provisional reference or prior writer output is supplied to either condition. Narrative cap: EN900 whitespace-separated words; KO3500 Unicode characters. Count both complete output and narrative separately; copied exact anchors, evidence quotes, JSON keys and IDs are excluded only from narrative count. The same requested cap is used for both conditions; actual enforcement is observational, not an API token limit. Exceedance is recorded rather than silently retried or truncated.

Use exact unique before/after replacement spans. A no-op is valid. The local applicator rejects ambiguous/missing/overlapping anchors and does not guess intended text. An invalid patch is an execution failure retained alongside the raw output, not rewritten by the orchestrator. Mechanical application is not semantic approval. Existing original text outside patches is byte-preserved, but appended text can still change its interpretation.

Shared questions:
Q1. What happened or was proposed, to whom, and with what decision/implementation or research status?
Q2. What does the supplied primary evidence establish, and what does it not establish?
Q3. Which conditions, comparisons, affected groups, counterarguments and time relationships materially change the reader's understanding?

Do not require every source detail merely because Q3 is broad. References must state materiality and eligibility. Unknown/partial claims remain visible outside confirmed-success denominators; no-answer and zero-opportunity outcomes are N/A rather than100%. All8 real outputs receive the same initial two reviewers and a third source-first audit, including unanimous passes. No result-based selection of all-pass audits.
