# Post-experiment delivery gate

**Holding a candidate returns the original unchanged, including its existing omissions and errors. Acceptance does not establish semantic correctness.**

`code/release_gate.py` is a pure, deterministic delivery wrapper over the original text, model patches, two saved review JSON objects, the expected packet ID, and expected source/candidate SHA-256 values. It calls the existing `apply_exact` on a copy. It never edits raw articles, model outputs, reviews, references, or core scores. It is neither another model condition nor an independent experiment.

The entire candidate is held if either reviewer reports meaning loss, overediting, a patch that is not warranted or correctly located, unsupported new meaning, an unknown structured assessment, unresolved material issues, or supported harm. A new assertion alone is allowed when evidence justifies it. Missing/incomplete reviews, missing/duplicate patch assessments, unexpected categorical values, packet/hash mismatches, and failed exact application also hold delivery. No patch is salvaged from a held candidate.

Reviewers must agree on structured patch judgments, overall flags, finding categories/verdicts, reference judgments, and question-scoped unanswered status/acknowledgment. Free-text explanations and anchors are not compared or treated as approvals. Unanswered components lack stable component IDs, so comparison uses the per-question multiset of statuses; ambiguous unlisted findings require resolution rather than inferred approval. Unknowns anywhere in those structured judgments conservatively hold, even where a later human might determine that they concern an original omission rather than introduced harm. This favors retention over coverage and is not a harm-rate estimator.

The evaluator schema does not embed content hashes in review JSONs. The replay runner checks each review's packet ID, verifies saved review-input and writer-output file hashes against the review map, verifies that the packet includes that writer output, and verifies source and displayed/proposed candidate hashes. Review-file hashes are recorded privately for audit, not independently authenticated signatures. The gate trusts the caller's expected hashes and cannot detect dishonest or substantively mistaken reviewers.

Replay: `python code/run_release_gate.py` from any directory. The existing 10 outputs and 20 reviews produced **10 holds, 0 accepts, 0 no-ops**. Original text was retained for all ten. Public quote-free decisions are in `results/release-gate-results.json`; proposed/delivered hashes, reasons, delivered text, and review provenance are retained privately in `/historical-research/journal-v12-private/release-gate-results.json`. Raw experimental failures and original scores remain unchanged.

Checks: `python code/test_release_gate.py` passes eight authored synthetic fixture tests: supported addition/input immutability, reviewer disagreement, unsupported change, stale source/candidate hashes, missing/incomplete reviews or assessments, no-op with review requirements, wrong packet/unknown/harm, and failed exact application. These are mechanical regression checks, not sampled model outputs, semantic validation, or evidence that the gate generalizes. No new model calls, web access, or authentication were used.
