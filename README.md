# Journal: 보도 설명의 근거와 의미 보존 실험

기사의 주장과 원자료·반증을 대조하고, 확인된 오류가 있는 문장이나 절만 수정하는 조사 방법을 연구합니다. 확인된 사실·책임·정당한 비판·발언 강도는 보존하고, 근거를 넘는 단정과 빠진 조건을 구분하는 것이 목표입니다.

이 저장소는 실제 실행 기록의 **공개용 파생본**입니다. 원자료 전문, 비공개 식별자, 실행환경 정보 등을 제거했으므로 최초 원파일과 바이트가 같은 보관본은 아닙니다. 새 모델 실행을 재현한 것처럼 꾸미지 않고, 실제 AI 출력·기계 조립·합성 대조·미실행 제안을 구분합니다.

## 결과부터 보기

**[검증자료 읽기 화면](docs/reader/index.html)**에서 v28까지 공개된 연구의 현재 쟁점, 수정 전후, 해당 근거와 미확인 사항을 함께 볼 수 있습니다. HTML 파일을 내려받아 브라우저로 열거나 저장소에서 직접 여세요. [사용법과 반영 범위](docs/verification-reader.md)에 재생성 방법을 적었습니다.

자료 읽기와 개인 검토를 분리했습니다. 개인 검토에서는 AI 판정을 명시적으로 펼치기 전까지 숨기며, 앞서 판정을 본 경우 그 사실을 기록합니다. 개인 입력·저장·내보내기는 기존 연구 결과나 사람 검토 수를 바꾸지 않습니다. 공개되지 않은 기사 문장을 요약문으로 대신 인용하지 않습니다.

현재 통합 상태는 [v28 직접자료·남은 차단](experiments/v28/DIRECT-EVIDENCE-STATUS.md), [평가 정정](experiments/v28/RESULTS.md), [통합 변경과 우선순위](docs/v15-v28-integration.md)에 있습니다. 원격 main의 원자료·AI 검토 후속 작업(#4)을 보존하고 v15~v28 로컬 연구를 합쳤습니다. 되돌려진 v14와 별도 검토 중인 PR #7은 이번 통합에 포함하지 않습니다.

발전량의 추정 상태와 PS의 분석 범위를 국소 수정했지만, 보호항목의 완전성·귀속 판단 재현성·일반 성능은 해결되지 않았습니다. 새 저자 슬라이드는 배치와 모델 관계를 보강했으나 최종 논문 전문이나 전문가의 추가 발언 기록을 대신하지 않습니다. 새 AI 실행 없이 저장 결과와 공개용 검사만 재검증했습니다.

후속 [원자료·AI 평가 검증](experiments/source-evidence-ai-review/)에서는 미확보 법원 3사건의 로컬 검토 자료 6개를 확보하고, 최신 AI 작업답안 12개·근거 위치 55개를 검사했습니다. 별도의 재사용 한국은행 원문에서 합성 문장 18개를 검토해 승인11·수정6·보류1을 기록하고, 수정6개·추가근거1개를 후속 확인했습니다. 공개본은 저장 판정과 문구 연결을 재검증하며 인간 중요도 일치·일반 성능의 증거로 제시하지 않습니다. 과거 v6 점수는 유지합니다.

**검증된 일반 해법은 아직 없습니다.** 보호해야 할 의미 목록의 완전성, 평가 AI의 공통 오류, 한국어·영어 전체기사로의 일반화는 해결되지 않았습니다. v8에서 양 언어 모두 실제 수정 성공이 있었지만 작은 필요수정 분모·매체 구성 차이·원자료 부족 때문에 일반 성능으로 해석하지 않습니다. v7의 4/4와 3/4 차이를 통계적 우월성이나 정치적 편향 감소로 해석하지 않습니다.

검토의 ‘독립’은 작성과 분리된 새 AI 문맥을 뜻합니다. 인간 평가나 확인된 다른 모델 계열 비교가 아닙니다. 정확한 배포 모델·seed·청구 비용은 미확인입니다. v9까지 실제 다른 모델 계열 비교는 0건이며 문헌 리서치와 미실행 설계를 실행 결과로 세지 않습니다. v7 BEA 사례는 v6와 다른 분기 발표지만 같은 기관·상쇄 관계의 전이입니다. 과거 연구 전체에서 미노출이었는지는 확인하지 못했습니다.

## 사용 방법

Python 3.11 이상에서 공개 자료 점검과 회귀·집계 검사를 실행합니다. v13 JSON Schema 검사에는 아래 고정 의존성이 필요하며 나머지 기본 검사는 표준 라이브러리를 사용합니다.

```sh
python -m pip install -r requirements-research.txt
python tools/run_checks.py
```

새 T 완료 평가 집계에는 [v19 checked 집계기](experiments/v19/code-audit/README.md)의 `score_T_checked_v2.py`를 사용합니다. 판단 ID뿐 아니라 realization 보고서 내부의 중복 case/method도 거부합니다. v7/v15 원코드와 과거 재생 경로는 보존합니다. 새 기사 입력의 식별자 검사가 필요하면 별도 `experiments/v19/code-audit/check_output_strict.py`를 사용하며, v18 원실험 재생은 동결 검증기를 계속 사용합니다.

각 회차의 README는 공개된 입력과 제외된 자료, 재실행 가능한 코드 범위를 설명합니다. 원문을 재배포하지 않으므로 이 저장소만으로 최초 원문 입력을 포함한 모델 실행을 완전히 재현할 수는 없습니다. 외부 원자료는 해당 출처의 접근 조건과 권리를 확인해 별도로 확보해야 합니다. API 키나 유료 실행은 검사에 필요하지 않습니다.

## 조사·편집 절차

1. 질문·자료 버전·사건일·발표/수정일을 고정합니다.
2. 원문의 주체·수치·조건·반론 대상·발언 강도·시간·비교 관계를 근거 위치와 연결합니다. 목록은 잠정적입니다.
3. 별도 검토가 원문을 다시 보며 목록 밖 주장과 누락을 확인합니다.
4. 확인된 오류가 있는 최소 절만 수정하고 나머지 바이트와 주변 의미를 대조합니다.
5. 원문→출력의 필요한 의미 보존과 출력→원문의 주장 지지를 따로 검사합니다. 새 오류·불확실성·범위 초과가 남으면 수정안을 보류하거나 되돌립니다.

롤백은 오류 해결 성공이 아닙니다. 분량 안에 조건을 보존할 수 없다면 압축 불가 또는 길이 증가 필요를 표시합니다. 질문 범위의 검증과 전체 원문 감사를 구분합니다.
