# 검증자료 읽기

[읽기 화면](reader/index.html)은 v28까지 Git에 공개된 연구 자료를 사용합니다. 원문·수정·근거를 항목별로 연결하고, 보류 이유와 확인하지 못한 내용을 함께 보여줍니다. 새 AI 실행이나 새로운 사실 판정은 하지 않습니다.

## 열기

저장소를 내려받은 뒤 `docs/reader/index.html`을 브라우저로 여세요. HTML 안에 화면 코드와 데이터가 들어 있어 서버나 추가 설치가 필요하지 않습니다. 원자료와 상세 연구 기록의 외부 링크를 열 때는 인터넷 연결이 필요합니다. GitHub의 HTML 파일 화면 자체는 미리보기를 제공하지 않습니다.

- **자료 읽기:** 쟁점을 고르고 기사 표현·수정 또는 평가 정정·원자료 연결·미확인을 확인합니다.
- **직접 평가하기:** 개인 판단을 적고 브라우저에 저장하거나 파일로 내보냅니다. AI 판단을 봤는지와 독립성의 한계가 함께 기록됩니다.
- **입력 기사와 근거:** 검토한 기사 링크와 이를 대조한 논문·공식 자료 링크를 구분해 제공합니다. 합성 변형 사례는 외부 원기사와 실험 입력의 관계를 별도로 설명합니다. 원제목이 없는 경우 설명용 이름임을 표시합니다.
- **원자료:** 정확히 공개된 인용, 보고서의 요약, 공개되지 않은 구절을 구별합니다. PDF는 가능한 경우 해당 쪽으로 연결하며 PDF 뷰어에 따라 쪽 이동 지원이 다를 수 있습니다.
- **연구 기록:** 회차별 원보고서, 실행·정정 기록과 기존 평가 한계를 확인합니다. 가능한 경우 판단에 해당하는 문서 절로 바로 연결합니다.

작은 화면에서는 목록이 접혀 있습니다. ‘항목 N개 · 목록 열기’를 눌러 검색·필터를 사용하고 항목을 고르면 본문으로 이동합니다. 현재 주소에는 선택 항목과 읽기 방식이 들어 있으므로 같은 주소를 다시 열거나 새로고침하면 그 항목이 유지됩니다. 기본 파일을 새로 여는 것과는 다르며, 저장한 메모는 복원 버튼으로 직접 불러옵니다.

접근 확인에서 막힌 원자료는 확인일과 제한을 표시합니다. 자동 접근 실패가 브라우저에서도 열리지 않는다는 뜻은 아닙니다. PDF 쪽 번호가 직접 확인되지 않은 경우에는 임의의 쪽 이동 링크를 만들지 않습니다.

## 새 기사 검토

저장소의 `docs/reader` 폴더를 함께 둔 상태에서 [기사 팩트체크](reader/factcheck.html)를 여세요. 기사 본문과 대조할 원자료는 직접 제공합니다. 입력과 판정은 브라우저 안에서 처리합니다.

1. 제목과 본문을 붙여 넣고 검토 목록을 만드세요. 처음 사용하는 경우 ‘가상 정치 기사로 연습’을 누르면 기사와 모의 원자료가 열립니다.
2. 원자료 주소, 판본 또는 기준일, 위치, 확인한 구절을 등록하세요. ‘원자료 본문에서 근거 구간 찾기’는 주장과 표현이 겹치는 문단을 최대 세 개 보여 줍니다. 금액이 같은 다른 연도의 행이나 주장을 반박하는 행도 나옵니다. 질문의 기준 시점이 표 첫 칸의 연도·월과 다르거나 명시된 적용기간에서 벗어나면 두 시점을 나란히 표시합니다. 날짜가 다른 열에 있거나 질문이 여러 시점을 비교하면 원표 머리글을 직접 확인하세요. ‘표 12’처럼 번호를 넣었는데 제목이 여러 개 뜨면 원하는 표인지 확인하세요.
   “증가 폭이 반토막”처럼 대상이 빠진 문장은 **기사에서 비교 대상·기간 보충**을 여세요. 입력해 둔 기사의 첫 줄이나 현재 문장의 앞뒤 구절로 다시 검색할 수 있고, 직접 확인한 지표와 기간을 적을 수도 있습니다. 어떤 문맥을 사용했는지는 입력란에 남습니다. ‘올해’와 같은 표현의 연도는 기사 발행일과 대조하세요. 질문이 요구하는 단위나 조사 사유를 자료에서 식별하기 어려우면 화면이 확인할 내용을 먼저 알려줍니다. 표현이 겹친 위치는 필요할 때 펼쳐 볼 수 있습니다.
   연도 머리글과 수치 열이 일대일로 맞으면 후보 옆에 해당 열의 번호와 원문 값을 표시합니다. 예를 들어 같은 2022년 열이 두 개면 두 값이 모두 표시됩니다. 어느 선거·매체에 속한 값인지는 원표의 상위 제목에서 확인하세요.
   항목이 세로로, 연도가 가로로 놓인 표에서는 질문에 나온 행부터 볼 수 있습니다. 후보의 **연도 열 직접 대조**를 누르면 해당 행과 연도로 원표를 엽니다. 다른 위치는 **원표의 행과 연도 직접 선택**에서 고르세요. 표시된 값과 원본의 단위·대상을 대조하고 발췌 버튼을 누르면 원문 행과 위치를 자료 입력란으로 옮깁니다. 표 번호와 제목을 함께 붙여 넣었다면 발췌 위치에도 남습니다.
   같은 항목의 두 연도에 같은 비율이 적혀 있고 괄호 속 증감이 반올림으로도 설명되지 않으면, 해당 열을 물었을 때 화면에 두 원문 값을 함께 표시합니다. 편집자는 조사보고서·통계표를 대조해 인용할 값과 위치를 선택합니다. 실제 독서실태조사의 경우 보도자료 표에는 47.5(-4.5)가 인쇄됐고, 원보고서의 2023년 값은 43.0%였습니다. [근거 위치와 대조 기록](../experiments/evidence-retrieval-transfer/third/source-check.md)
   후보에 금액만 있고 비교 연도·단위가 빠졌다면 **주변 원문 확인**을 여세요. 표 머리글과 후보 앞뒤 최대 12문단을 볼 수 있습니다. 붙여 넣은 자료에 쪽 나눔이 남아 있으면 그 경계에서 멈춥니다. 행을 골라 **선택한 행을 발췌문으로 사용**을 누르면 그 원문 행만 옮겨집니다. 문단 번호는 붙여 넣은 글 안의 위치이므로 원본에서 다시 찾을 수 있는 쪽·표·행도 기록하세요.
3. 기사 문장 옆에서 원자료를 대조해 판단과 이유를 기록하세요. 예를 들어 의원이 시장의 예산 은폐를 주장했다면 회의록에서는 **의원의 발언 여부**를 확인할 수 있습니다. **시장이 예산을 숨겼다는 주장**은 미확인으로 남습니다. 내용까지 확인하려면 회계 기록 등 독립된 원자료를 따로 연결하세요. 비판의 강도와 발언자는 그대로 남기고, 근거를 확보한 부분과 확인이 필요한 부분을 구분하세요.
4. 자료가 충돌하면 시점·대상·분모와 정정 이력을 먼저 확인하세요. 자료 선택란은 제목 옆에 판본을 함께 표시합니다. 비교 시점이 불분명하거나 사업 이후의 성과를 확인할 지표가 등록한 자료에 보이지 않으면, 자료 목록을 접어 두고 확인해야 할 내용을 알려줍니다. 원하는 자료는 직접 펼쳐 볼 수 있습니다. 예산 요구액을 확인하는 경우에는 요구서를, 실제 의결액을 확인하는 경우에는 의결 기록을 직접 대조하세요. 문장 검토에서 원자료 입력이나 근거 찾기를 열었다면 ‘N번 문장의 대조 자료로 추가’로 돌아가세요. 앞서 입력한 판단 이유와 선택한 자료가 남고, 최종 판정은 근거를 확인한 뒤 직접 기록합니다. 같은 보도자료를 옮긴 기사 여러 건은 같은 출처입니다. 최초 원문 주소를 기록해 두면 중간 통신사나 재인용 기사를 거친 경우에도 같은 발언을 그 내용의 독립 근거로 선택하는 일을 막습니다. 여당과 야당, 칭찬과 비판에 같은 기준을 적용하세요. 문장에 적힌 사실을 모두 확인해도 제목이 좁은 집단을 전체로 넓혔는지, 반대되는 기록을 누락했는지는 별도로 살펴야 합니다.
5. ‘기사 평가’에서 제목·핵심 주장의 판정과 사실 확인 범위를 확인하세요. 편향을 평가할 때는 표현·귀속, 제목·도입부, 근거·맥락, 당사자별 검증 기준을 각각 살펴보고 판단 근거를 기록하세요. [네 항목의 단계별 판정표](article-rubric.md)

발언을 정확히 인용했는데 내용이 직접 증거와 어긋나면 ‘발언자·인용 내용 확인 → 발언 내용이 별도 원자료와 충돌’을 선택합니다. 원발언과 독립된 원자료를 각각 고르고, 발언 당시의 같은 대상·기간·단위에서 어떤 사실이 양립할 수 없는지 적습니다. 발언을 잘못 옮겼거나 발언 주체를 바꾼 경우에는 원문 자체의 충돌로 검토합니다.

“집행액이 20억 원이라고 말한 적 없다”는 부인을 검토할 때 과거 녹취로 확인할 수 있는 것은 그 말을 했는지입니다. 실제 금액을 확인하려면 같은 기간의 결산 자료가 필요합니다. 질문·약속·조건이나 여러 주장이 섞여 반박 대상을 한 구절로 특정하기 어려우면 원발언을 확인한 뒤 ‘발언 내용 미확인’으로 기록하고 이유를 남깁니다. 이전 작업 파일에서 이런 구절을 숫자 반증으로 기록했다면 다시 열 때 재검토 대상으로 돌아갑니다.

“내년 예산은 이미 20억 원으로 확정됐다”는 발언은 발언 당시 의결된 금액을 당시 의결표와 대조합니다. “내년에 20억 원을 쓰겠다”는 약속의 이행 여부는 그 시점의 의결표로 판단할 수 없습니다. “지난해 집행액은 20억 원”처럼 서술어가 생략된 인용도 대상과 금액이 분명하면 결산표로 검토할 수 있습니다.
6. 이어서 작업할 때는 작업 JSON을 저장하고 다시 여세요. 독자에게 전달할 때는 기사 평가와 문장별 근거, 미확인 범위가 담긴 결과를 내려받으세요. 원문이 근거와 충돌하면 해당 문장을 대체할 정정 문구도 원자료와 대조한 뒤 함께 기록할 수 있습니다. 작업 파일에는 입력 기사와 선택한 발췌문이, 결과 파일에는 기사 문장 전체가 들어갑니다. 외부에 전달하기 전에 기사의 재배포 허용 범위를 확인하고, 필요하면 원문 링크로 대신하세요.

PDF 원자료는 표지를 1쪽으로 세는 **PDF 파일 쪽번호**를 따로 입력할 수 있습니다. 인쇄된 쪽수, 표 제목, 행과 기준연도는 확인 위치에 적으세요. 기사 문장 옆의 PDF 링크는 기록한 파일 쪽을 가리킵니다. 원자료 사이트가 파일을 내려받게 하면 같은 판본의 로컬 PDF를 연결해 그 쪽을 열 수 있습니다. 연결한 파일은 그 탭에서만 사용하며 작업 JSON에는 주소·판본·위치가 남습니다.

사람이 확인하고 기록한 판단만 재사용합니다. 기사나 근거 묶음이 달라지면 이전 판단의 적용 범위를 다시 살핍니다. 작업 파일은 작성자의 기록이므로 출처와 작성자를 확인한 파일을 사용하세요. 이 도구의 기록은 아래 v28 역사 자료와 따로 보관합니다.

## 두 작업 파일 비교

두 편집자가 독립적으로 평가하려면 한 사람이 **독립 평가용 기사·자료 내려받기**로 공통 입력을 만드세요. 두 사람은 같은 파일을 열고 각자 판단한 뒤 **작업 파일 내려받기**로 결과를 따로 저장합니다. 공통 입력에는 등록된 발췌문과 위치가 들어가고, 먼저 검토한 사람의 판단·핵심 구절 선정·편향 점수·초안은 빠집니다. 원자료를 고른 과정은 두 평가에 공통으로 영향을 줄 수 있습니다.

[평가 비교](reader/article-compare.html)에서 원본·수정본의 작업 JSON 또는 두 편집자가 서로의 답을 보기 전에 저장한 작업 JSON을 엽니다. 파일을 읽으면 같은 근거에 연결되는 판정만 재계산하고 수정 중인 판단은 집계에서 제외합니다. 원문 입력 자체를 바꾸는 중에 저장했다면 팩트체크에서 판본을 확정한 뒤 다시 저장하세요. [비교 지표와 분모](article-rubric.md#저장한-파일-비교하기)

## 반영 범위

연구 기준은 `research/integrate-v15-v28`의 공개 자료입니다. v28의 재감사 정정과 직접자료 확보, 그 이전 공개 연구 이력 및 원자료·AI 검토 후속 자료를 연결했습니다. 별도 검토 중인 v14 PR #7과 원격에 게시되지 않은 v28 이후 작업은 포함하지 않습니다.

기존 사람 1명의 중요도 응답 3개는 제한된 참고 응답입니다. 원문 독해·이유·동일 평가 조건 등이 확인되지 않았으며 인간 검증이나 일반 일치율의 근거로 바꾸지 않습니다. 이 화면의 개인 기록은 그 응답에 자동 합산되지 않습니다.

자료 전문과 PDF를 재배포하지 않는 [공개 원칙](../NOTICE.md)을 유지합니다. 공개 인용이 없는 항목은 해당 위치의 원자료로 이동해 확인해야 합니다. 요약문을 기사 원문이나 실제 수정문으로 표시하지 않습니다.

## 갱신

```sh
python tools/build_reader.py
python tools/run_checks.py
```

`docs/reader-data.json`에서 항목별 근거와 표시 종류를 관리하고, 생성기가 `docs/reader/index.html`을 만듭니다. 원기록을 바꾸는 작업과 읽기 화면 갱신을 구분하세요. 연구 결과를 새로 해석하거나 의미 판정을 바꾸려면 근거와 별도 검토가 필요합니다.

각 의견 입력란은 100,000자까지 보관합니다. 한도를 넘는 붙여넣기는 일부를 잘라 넣지 않고 거절하며, 저장과 내려받기도 같은 기준으로 검사합니다. 저장하지 않은 항목 수가 표시되고, 입력이 남은 채 페이지를 닫으려 하면 브라우저가 확인을 요청합니다. 브라우저가 경고를 지원하지 않는 경우도 있으므로 파일 보관을 함께 사용하세요. 내려받기는 완료 여부를 화면에서 확인할 수 없어 저장하지 않은 상태를 해제하지 않습니다.

회차별 연구 기록과 기술 정보에서 이 HTML에 포함된 근거 데이터를 그대로 내려받을 수 있습니다. 이후 저장소의 변경과 관계없이 현재 보고 있는 자료를 확인하는 용도입니다.

브라우저 저장은 기기·브라우저·파일 열기 방식에 따라 제한되거나 지워질 수 있습니다. 중요한 개인 기록은 파일로도 내려받아 보관하세요. 저장 실패 시 내보내기를 사용할 수 있습니다. 실제 사람의 사용성 평가는 이번 구현 검사와 별개입니다.

## 화면 동작 회귀 검사

Node.js 24에서 `npm ci --ignore-scripts` 후 `npm test`를 실행합니다. 생성된 HTML을 jsdom에서 실행하여 저장·복원, 가져오기, 입력 유실 방지, AI 노출 이력과 근거 데이터 내보내기를 검사합니다. 실제 브라우저의 렌더링이나 사람 사용성 평가를 대신하지 않습니다. Python 전체 검사와 이 검사를 GitHub CI에서 함께 실행합니다.
