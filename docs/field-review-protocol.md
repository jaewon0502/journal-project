# 실제 기사 검증 파일럿

[참여자 측정 화면](reader/field-review.html)에서 원자료를 직접 찾는 시간부터 잽니다. [진행자 집계 화면](reader/field-summary.html)에서는 같은 과제를 평소 도구로 검증했을 때와 저널을 함께 썼을 때의 시간, 근거를 다시 찾은 건수, 판정이 맞은 건수를 확인합니다.

## 배부용 파일

진행자용 `집계도구.zip`을 받았다면 압축을 풀고 `시작.html`을 여세요. ‘실제 기사에서 원자료 찾기’에서 기사를 고른 뒤 평소 도구용·저널 병행용 ZIP을 바로 받을 수 있습니다. 한 화면에서 받은 같은 기사의 두 ZIP은 배포본 ID가 같으므로 시간 절감률을 비교할 수 있습니다. 참여 코드와 함께 각자 배정받은 ZIP 하나를 전달하세요.

배정표에 맞는 압축 파일 하나만 참여자에게 전달하세요. 압축을 풀고 `field-review.html`을 열면 배정 방식과 과제 번호 목록이 표시됩니다. 참여자는 진행자에게 받은 배정 코드를 붙여 넣어 과제와 익명 코드를 확인합니다. 번호와 익명 코드를 따로 받았다면 직접 입력할 수 있습니다. 목록이 보이지 않으면 ‘과제 파일 직접 불러오기’에서 같은 폴더의 `blind-tasks.json`을 여세요. 두 방식의 문항은 같고, 저널 방식에는 기사 팩트체크 도구가 들어 있습니다. 채점표는 진행자가 보관합니다. 저장소 루트에서 아래 명령을 실행하면 다운로드 폴더의 `Journal-편집자-파일럿`에 두 방식의 배포본이 생깁니다. [배부본 생성기](../tools/build_field_participant_packs.py)

| 사례 | 배포본 생성 | 파일 위치 |
|---|---|---|
| 2025년도 예비비 | `python3 tools/build_field_participant_packs.py` | 기본 폴더 |
| 2024년 연간 고용 | `python3 tools/build_field_participant_packs.py --case labour-field-review` | 기본 폴더 안 `labour-field-review` |

## 참여 전

- 진행자는 [예비비 과제](../experiments/cross-party-review/blind-tasks.json) 또는 [고용 과제](../experiments/labour-field-review/blind-tasks.json)를 사용합니다. 해당 과제를 처음 보는 편집자·팩트체커에게 익명 코드 하나를 배정하세요. 인터넷에 연결된 브라우저로 참여할 수 있습니다. 참여 화면은 과제 제목·번호만 먼저 보여 줍니다. 기사 링크와 과제 문장은 시계를 시작하면 표시됩니다.
- [현장 기사 과제 배정](reader/field-allocation.html)에서 참여자용 과제 파일을 열고, 모집한 순서대로 이름 대신 익명 코드를 한 줄에 하나씩 입력하세요. 과제와 방식의 조합을 묶음 안에서 무작위로 섞습니다. 답안을 받기 전에 배정표 JSON을 저장해 보관하세요. 저장한 명부는 같은 화면에서 다시 열 수 있습니다. 각 행에서 ‘코드 복사’를 눌러 그 사람의 배정 코드와 해당 ZIP을 전달하세요. 코드는 과제와 배포본이 맞는지 확인하는 데 쓰이고, 현업 참여 여부는 본인이 따로 선택합니다. 예비비의 첫 묶음은 아래 네 조합입니다. 고용은 `labour-growth`, `labour-rate`, `labour-period` 각 2장으로 첫 묶음에 6명이 필요합니다. 같은 원표를 다시 찾는 학습 효과를 줄이기 위해 한 사람은 같은 기사에서 한 과제만 수행합니다. 연습에는 다른 기사를 쓰세요.
- 두 방식 모두 원보도와 웹 검색을 사용할 수 있습니다. 저널 방식에는 팩트체크 작업 화면이 추가됩니다. 시작 전에는 정답 파일, 기사 평가용 작업 JSON, 조정자 메모, 다른 참여자의 결과를 보여주지 마세요. 과제의 문장은 연구자가 검증용으로 작성했습니다.

| 배정표 | 과제 | 검증 방식 |
|---|---|---|
| 1 | reserve-plan | 평소 검증 도구 |
| 2 | reserve-plan | 평소 검증 도구와 저널 |
| 3 | reserve-settlement | 평소 검증 도구 |
| 4 | reserve-settlement | 평소 검증 도구와 저널 |

## 측정

1. 참여자가 파일을 열고 받은 배정 코드를 확인합니다. 다른 기사나 방식의 ZIP이면 해당 배포본을 다시 확인하세요. 배정 코드에는 질문 문장과 답이 들어 있지 않습니다. 직접 입력할 때는 진행자가 알려 준 과제 번호와 익명 코드를 사용하세요. 현업 참여자는 ‘현업 편집자·팩트체커 본인 참여’를 직접 선택합니다. ‘시간 측정 시작’을 누르면 과제 문장과 기사 링크가 나타나고 측정이 시작됩니다. 연습은 별도 집계됩니다.
2. 기사 문장을 읽고 외부에서 원자료를 검색할 때는 ‘원자료 찾기’, 문서 안의 표·행·발언을 찾을 때는 ‘표·발언 위치 찾기’, 최종 판단을 적을 때는 ‘판정 기록’을 누릅니다. 원문으로 되돌아가면 해당 단계를 다시 선택하세요. 단계 단추를 뒤늦게 누른 경우에는 제출 전에 ‘단계 전환을 놓쳐 총시간만 사용’을 선택하세요. 전체 활동 시간은 그대로 집계하고 해당 기록은 단계별 평균에서 제외합니다. 휴식을 직접 누른 구간만 제외합니다. 휴식 중에는 외부 탭에서도 검증을 멈춰 주세요.
3. 찾은 원자료 주소와 위치, 실제 확인한 값 및 이유를 제출합니다. 찾지 못했다면 그 사실도 제출합니다. 무리하게 판단할 필요가 없으며 ‘근거 부족’도 유효한 판정입니다. 완료 시에는 배정과 관계없이 저널을 실제 사용했는지도 응답합니다. 완료 또는 중도 종료 후 참여 JSON을 저장합니다. 같은 기기를 돌려 쓰면 먼저 해당 파일을 보관하고 ‘새 과제’를 누릅니다.

## 집계

가능하면 두 방식의 답안을 모아 한꺼번에 불러오세요. 처음에는 참여 코드와 도구 배정을 가리고 답안 순서를 섞습니다. 제출한 원자료 주소와 표·행·열을 기준표와 대조해 채점한 뒤 ‘배정과 결과 보기’를 눌러 소요 시간과 성공률을 확인하세요. 결과를 본 뒤 수정할 때는 ‘배정 가리고 채점하기’를 누릅니다. 한 번 본 배정이나 답안에 직접 적힌 도구 이름으로 방식을 짐작할 수 있습니다. 참여자에게는 판단 이유에 사용한 도구 이름 대신 확인한 값과 근거 위치를 적어 달라고 안내하세요.

진행자 화면에서 해당 기사의 기준 파일과 참여 JSON을 불러옵니다. **근거 위치**는 제출된 주소에서 해당 표·행·열·시점을 직접 다시 찾아 채점합니다. 기준 파일에는 다른 표에서 같은 수치를 찾을 수 있는 경우도 적혀 있습니다. **판정**은 사례·기사 주소·과제 번호·문장이 기준 파일과 일치할 때 자동 대조됩니다. 같은 URL을 제출해도 다른 열을 읽으면 위치 재확인에 실패할 수 있습니다. [예비비 기준 파일](../experiments/cross-party-review/coordinator-key.json) · [고용 기준 파일](../experiments/labour-field-review/coordinator-key.json)

같은 탭에서 새로고침하면 불러온 채점 기준, 참여 기록과 수동 채점을 복원합니다. 탭을 닫거나 기기를 옮기기 전에는 ‘판정과 집계 기록 저장’으로 JSON을 내려받으세요. 현업 참여와 연습을 모두 채점했다면 구분을 바꿔 각각 저장하세요. 브라우저에서 임시 저장을 막은 경우에는 화면에 알림이 뜹니다.

같은 답안을 다르게 채점한 집계 파일을 함께 열면 과제 문장, 제출한 근거 위치 또는 이유, 채점이 갈린 항목이 표시됩니다. 화면에 이미 불러온 기록은 그대로 남습니다. 두 원본을 따로 보관하고, 표시된 자료를 다시 대조해 사용할 채점을 정한 뒤 가져오세요.

각 답안의 ‘채점 근거와 추가 허용 자료’를 열면 기준 판정에 사용한 계산이나 설명과 원표 외에 허용한 자료를 확인할 수 있습니다. 예를 들어 고용 기사의 집계 연도 과제에서는 통계청 PDF와 공식 게시물 본문 모두에서 기준 수치를 대조할 수 있습니다.

- **위치 재확인 성공률**은 위치가 맞은 완료 건수 ÷ 위치 채점 완료 건수입니다. ‘찾지 못함’은 실패에 포함하고, 진행자가 아직 보지 않은 답안 수는 별도로 표시합니다.
- **근거 위치와 판정 모두 일치**는 한 응답에서 두 항목을 모두 맞힌 비율입니다. 예를 들어 두 사람 중 한 명은 위치만 맞히고 다른 한 명은 판정만 맞히면 각각 1/2이지만 둘 다 맞힌 응답은 0/2입니다. 분모에는 성공이나 실패를 확정할 수 있는 완료 응답을 넣습니다. 어느 한 항목이라도 틀렸거나 자료를 찾지 못했다면 실패로 셉니다. 남은 채점에 따라 결과가 바뀔 응답은 대기에 표시합니다. 중단 후 복원으로 시간이 불완전해도 제출한 근거와 판정은 채점할 수 있습니다.
- **과제별 시간 절감률**은 (평소 도구 평균 활동 시간 − 저널 병행 평균 활동 시간) ÷ 평소 도구 평균 활동 시간 × 100입니다. 같은 배포본 ID, 기사 주소, 과제, 문장의 양쪽 완료 기록이 있어야 계산하며, 기준이 0초면 초 차이만 표시합니다. 더 오래 걸린 과제도 그대로 표시합니다. 두 방식의 건수와 그중 근거 위치와 판정이 모두 맞은 건수, 채점 대기도 나란히 확인하세요. 한쪽 참여자가 어려운 과제를 더 많이 받으면 전체 평균이 왜곡될 수 있어 사례·과제를 합친 절감률은 내지 않습니다.
- **판정 일치율**은 기준과 일치한 건수 ÷ 판정 채점 완료 건수입니다. **근거 없는 사실 채택률**은 정답이 반박·근거 부족인 완료 과제에서 지지로 제출한 비율입니다. 해당 과제가 없으면 산출을 보류합니다.
- **검증 성공 1건당 투입 시간**은 같은 배포본·과제·방식에서 수집한 완료·중도 종료 기록의 총 활동 시간을 근거 위치와 판정이 모두 맞은 완료 건수로 나눕니다. 오답과 중도 종료도 편집 시간이 들기 때문에 분자에 포함합니다. 중단 후 복원한 기록은 분자와 분모에서 함께 제외합니다. 한 항목이라도 불일치하면 성공 여부가 정해집니다. 남은 채점에 따라 성공 건수가 달라지거나 성공이 0건이면 해당 방식의 1건당 시간과 두 방식의 차이는 산출 대기로 표시합니다. 진행자가 전달받지 못한 중도 종료 기록의 시간은 반영할 수 없습니다.
- **사전 배정표로 확인한 현업 과제**에서는 전달 전에 보관한 명부와 각 참여자의 기사·과제·문장을 대조합니다. 맡은 과제를 다른 방식의 ZIP으로 했다면 원래 배정한 방식에 남기고 배포본이 달랐던 건수도 표시합니다. 다른 과제, 반복·배정 충돌, 중도 종료, 회수한 현업 기록이 없는 배정을 함께 봅니다. 예를 들어 6명에게 배정해 2명이 맡은 과제를 마쳤다면, 전체 배정은 6명이고 완료 시간 비교에는 그중 측정 가능한 응답만 들어갑니다. 나머지 네 명에게 시간을 0초로 입력하지 마세요.
- **기록상 방식별 검증 시간**은 참여 파일에 표시된 방식에 따라 계산합니다. 명부가 없는 예전 기록도 이 표에서 볼 수 있습니다. 본인이 실제 어느 도구를 썼는지는 별도로 물으며 예전 파일의 미응답은 미확인으로 표시합니다. 미제출자가 많거나 어려운 과제에서 이탈했다면 완료자의 시간 차이를 모집한 전체 편집자의 효과로 해석하기 어렵습니다.
- **시간 집계에 포함된 배포본**에서 어느 판본으로 측정했는지 확인합니다. 새로 만든 한 사례의 ‘평소 도구’와 ‘저널 병행’ ZIP에는 같은 배포본 ID가 들어갑니다. 과제를 시작할 때 참여 파일에 그 ID를 기록합니다. 예전 파일과 별도로 연 화면의 기록은 ‘버전 미확인’으로 표시합니다. 시간 차이와 절감률은 배포본별로 계산합니다. 여러 배포본을 합치면 시간이 짧은 판본에 한쪽 방식의 참여자가 몰린 것만으로 절감률의 방향이 뒤집힐 수 있습니다. 한쪽 방식만 있는 판본이나 버전 미확인 기록은 방식별 시간과 채점 건수를 확인할 수 있습니다. 이들 기록은 두 방식의 차이 계산에서 제외합니다.
- **총시간과 단계별 시간**은 과제·방식별 평균 초와 사용한 건수를 함께 보여 줍니다. 세 단계를 모두 표시한 과제만 단계별 평균에 들어갑니다. 중단 후 복원한 과제의 판단은 남기되 시간 평균에서 제외합니다. 같은 사람이 연습과 현업 참여에 같은 익명 코드를 쓰도록 안내하고, 진행자는 완료·중도 종료 기록을 함께 불러오세요. 같은 코드로 같은 사례나 같은 기사 주소를 두 번 이상 열었다면 그 기록 모두를 시간·품질 요약에서 제외합니다. 같은 파일을 두 번 불러와도 참여 횟수는 한 번입니다. 구분별 집계 파일에는 다른 구분의 원문 답안 대신 반복 노출 여부만 남습니다. 다른 코드로 참여했거나 앞선 기록을 받지 못했다면 반복을 식별할 수 없습니다. 중도 종료·미채점도 따로 셉니다.
- 집계 JSON에는 원기록, 채점, 적용한 기준의 원문·허용 위치·판정이 함께 저장됩니다. 기준을 담은 집계 파일을 불러오면 같은 사례·기사 주소·과제 번호·문장의 다른 참여 기록에도 그 기준을 적용합니다. 수동으로 매긴 판정 점수는 기준 판정으로 다시 계산하고, 기준 없이 채점했던 근거 위치는 진행자가 다시 확인합니다. 새 기준으로 바뀌면 판정을 다시 대조하고 위치는 새로 채점합니다. 기준 정보를 저장하지 않던 이전 자동 채점 파일은 기준 파일을 다시 불러와 위치를 재확인하세요. 모의 4개 기사의 균형 배정 실험과 실제 보도 파일럿은 서로 다른 자료입니다. 네 칸을 한 번 채운 결과는 참여자별 차이를 크게 받습니다. 시간 절감이나 정치 편향 감소의 일반적인 효과를 추정하려면 새로운 기사와 편집자 묶음으로 반복해야 합니다.
